# Отчёты в LibreOffice Base — ответы на вопросы к лабораторной работе №4

Примеры даны на учебной базе «Деканат» (таблицы `Преподаватель`, `Кафедра`, `Должность`, `Ученая_степень`, `Студент`, `Специальность`, `Дисциплина`, `Успеваемость`).

---

## 1. Почему отчёты являются важным элементом ИС БД?

Таблицы хранят данные, запросы их отбирают, формы служат для ввода. **Отчёты** предназначены для **вывода итоговой информации в готовом, оформленном виде**: на экран, на печать, в PDF.

Причины важности:

- **Результат работы ИС.** Именно отчёт чаще всего получает руководитель или заказчик (список преподавателей кафедры, ведомость успеваемости).
- **Структурирование данных.** Данные можно сгруппировать, отсортировать, подвести итоги (число преподавателей на кафедре, средний балл по дисциплине).
- **Оформление для печати.** Заголовок, колонтитулы, номера страниц, дата — документ готов к печати без доработки.
- **Не меняют данные.** Отчёт только отображает информацию, случайно испортить данные через него нельзя.
- **Доступность для пользователей без знания БД.** Пользователю не нужно уметь писать запросы: он открывает готовый отчёт.
- **Повторное использование.** Один раз созданный отчёт при каждом открытии показывает актуальные данные (динамический отчёт).

**Вывод:** отчёты замыкают цепочку «данные → запросы → документ для пользователя» и делают ИС источником готовых документов.

## 2. К какому уровню архитектуры ANSI-SPARC относятся отчёты?

Архитектура ANSI-SPARC состоит из трёх уровней:

| Уровень | Что описывает |
|---|---|
| **Внешний** | Представления данных для конкретных пользователей |
| **Концептуальный** | Логическая структура всей БД (сущности, связи, ограничения) |
| **Внутренний** | Физическое хранение данных (файлы, индексы) |

**Отчёты относятся к внешнему уровню** (так же как формы и запросы). Это то, что **видит пользователь**: часть данных БД, представленная в удобном для него виде. Один и тот же набор таблиц (концептуальный уровень) может порождать множество разных отчётов для разных категорий пользователей: деканата, кафедры, студентов.

## 3. Как создать отчёт в режиме дизайна?

1. В главном окне Base слева выбрать **«Отчёты»**.
2. Нажать **«Создать отчёт в режиме дизайна…»**. Откроется **Конструктор отчётов (Report Builder)**.
   > Если пункт недоступен, нужно установить расширение *Report Builder* (в некоторых версиях LibreOffice оно встроено).
3. **Задать источник данных.** Открыть **Свойства отчёта** (*Правка → Выбор отчёта*, затем окно свойств, или кнопка «Свойства») → вкладка **«Данные»**:
   - **Тип содержимого:** *Таблица*, *Запрос* или *SQL-команда*;
   - **Содержимое:** выбрать нужную таблицу или запрос, например `Преподаватель`.
4. **Добавить поля.** Меню **Вид → Добавить поле** открывает список полей источника. Перетащить нужные поля в раздел **«Подробности»**. Каждое поле вставляется вместе с меткой-подписью.
5. **Разместить подписи.** Метки (названия столбцов) перенести в раздел **«Верхний колонтитул страницы»**, чтобы они печатались один раз над таблицей на странице. В «Подробностях» остаются только поля данных.
6. **Заголовок и колонтитулы.** Включить разделы через **Правка → Разделы → Заголовок/Нижний колонтитул отчёта и страницы** и добавить в них надписи, дату, номера страниц.
7. **Группировка и сортировка** (при необходимости): **Вид → Сортировка и группировка**.
8. **Выровнять и оформить** элементы: шрифт, границы, цвета, ширину.
9. Сохранить отчёт (**Ctrl+S**), дать имя.
10. Проверить результат кнопкой **«Выполнить отчёт»** (на панели инструментов).

## 4. Как создать отчёт в режиме мастера?

1. В главном окне Base выбрать **«Отчёты»**.
2. Нажать **«Использовать мастер для создания отчёта…»**.
3. Последовательно пройти **6 шагов мастера** (подробно в вопросах 5–10):
   1. Выбор полей
   2. Обозначение полей (метки)
   3. Группировка
   4. Параметры сортировки
   5. Выбор разметки
   6. Создание отчёта
4. На последнем шаге нажать **«Готово»**. Отчёт откроется (или откроется в режиме правки, в зависимости от выбранного варианта).

**Плюсы:** быстро, не нужно ничего вёрстывать вручную.
**Минусы:** ограниченные возможности оформления, поэтому готовый отчёт часто дорабатывают вручную.

---

## 5. Первый шаг мастера отчётов — «Выбор полей»

На этом шаге определяется, **какие данные попадут в отчёт**.

Что делаем:

1. В списке **«Таблицы или запросы»** выбираем источник данных (например, таблицу `Преподаватель` или запрос).
2. В списке **«Доступные поля»** выбираем нужные поля.
3. Переносим их в **«Поля в отчёте»**:
   - `>` — перенести выделенное поле;
   - `>>` — перенести все поля;
   - `<` и `<<` — вернуть обратно.
4. Порядок полей в правом списке определяет порядок столбцов в отчёте.

**Особенность:** можно взять поля из **нескольких** источников (повторно выбрать другую таблицу или запрос и добавить поля). Но чтобы данные из разных таблиц правильно соединялись, **удобнее строить отчёт на одном запросе** (см. вопрос 11).

**Пример:** выбрать из `Преподаватель` поля `ФИО`, `Должность`, `Учёная степень`.

---

## 6. Второй шаг мастера отчётов — «Обозначение полей» (поле меток)

На этом шаге задаются **подписи (метки)** — **заголовки столбцов**, которые увидит пользователь в отчёте.

- Слева перечислены **имена полей**, справа — поле **«Метка»** для каждого.
- По умолчанию метка совпадает с именем поля.
- Чтобы изменить, нужно ввести новый текст напротив нужного поля.

**Пример:**

| Поле в БД | Метка в отчёте |
|---|---|
| `Номер_зачетки` | № зачётной книжки |
| `ФИО` | Фамилия, имя, отчество |
| `Дата_рождения` | Дата рождения |

Заполнять метки стоит, когда имена полей **технические** (содержат `_`, сокращения, латиницу). Подробнее в вопросе 13.

---

## 7. Третий шаг мастера отчётов — «Группировка»

На этом шаге записи **объединяются в группы по значению выбранного поля**. Для каждой группы выводится отдельный заголовок, под ним записи, относящиеся к ней.

Что делаем:

1. В списке **«Поля»** выбираем поле для группировки.
2. Переносим его кнопкой `>` в список **«Группировка»**.
3. Можно задать **несколько уровней** группировки. Порядок в списке определяет вложенность (первое поле — внешняя группа, второе — внутренняя). Порядок меняют кнопками со стрелками вверх/вниз.
4. Если группировка не нужна, список остаётся пустым.

**Пример:** отчёт «Преподаватели по кафедрам». Группировка по полю `Кафедра`:

```
Кафедра: Алгебры и геометрии
    Иванов И.И.    Профессор
    Петров П.П.    Доцент
Кафедра: Математического анализа
    Сидоров С.С.   Доцент
    ...
```

Поле, по которому сгруппировали, в «Поля в отчёте» дублировать не нужно: оно выводится один раз в заголовке группы.

---

## 8. Четвёртый шаг мастера отчётов — «Параметры сортировки»

На этом шаге задаётся **порядок записей** внутри отчёта (или внутри групп, если была группировка).

Что делаем:

1. В выпадающих списках **«Сортировать по»** (до **четырёх** уровней) выбираем поля.
2. Для каждого поля выбираем направление:
   - **По возрастанию** (А→Я, 0→9, старые даты → новые);
   - **По убыванию** (Я→А, 9→0).
3. Второй, третий и четвёртый уровни срабатывают, если значения предыдущего уровня совпадают.

**Пример:** сортировка преподавателей по `ФИО` по возрастанию. Или сначала по `Должность`, затем по `ФИО`.

Если группировка задана, поля группировки автоматически сортируются по возрастанию, а настройки шага относятся к записям внутри групп.

---

## 9. Пятый шаг мастера отчётов — «Выбор разметки»

На этом шаге определяется **внешний вид отчёта**: как расположены данные и оформление страницы.

Основные параметры:

1. **Макет данных** (расположение полей в «Подробностях»):
   - **Табличный** — записи в строках, поля в столбцах;
   - **В столбцах (один столбец)** — «карточка», поля друг под другом, подписи слева;
   - **В столбцах (два / три столбца)** — то же, но в несколько колонок на странице;
   - **Блок (подписи слева / сверху)** — блочное расположение.
2. **Макет заголовков и колонтитулов** — выбор стиля оформления из списка (шрифты, цвета, линии).
3. **Ориентация страницы:** **книжная** или **альбомная**. Если столбцов много и они не помещаются по ширине, выбирают альбомную.

В окне справа показывается **предварительный образец** выбранной разметки.

---

## 10. Шестой шаг мастера отчётов — «Создать отчёт»

Завершающий шаг. Здесь нужно:

1. **Ввести заголовок отчёта.** Он будет напечатан в самом верху.
2. **Выбрать тип отчёта:**
   - **Динамический отчёт** — при каждом открытии данные берутся из БД заново (всегда актуальный);
   - **Статический отчёт** — «снимок» данных на момент создания (см. вопрос 16).
3. **Выбрать дальнейшее действие:**
   - **«Создать отчёт сейчас»** — показать готовый отчёт;
   - **«Изменить разметку отчёта»** — открыть отчёт в режиме редактирования для доработки.
4. Нажать **«Готово»**. Отчёт сохраняется в разделе **«Отчёты»**, потребуется ввести имя.

## 11. Что лучше? Строить отчёты на основе данных таблиц или данных запроса?

**В большинстве случаев лучше строить отчёт на запросе.**

| | Таблица | Запрос |
|---|---|---|
| Данные из нескольких таблиц | Нельзя (одна таблица) | Можно (JOIN), вместо кодов выводим названия |
| Отбор записей | Все записи | Только нужные (`WHERE`, параметры) |
| Вычисляемые поля и итоги | Нет | Есть (`AVG`, `COUNT`, выражения) |
| Сортировка | Только в отчёте | Можно и в запросе (`ORDER BY`) |
| Простота | Очень просто | Нужно сначала создать запрос |

**Когда достаточно таблицы:** простой список из одной таблицы без отбора (например, «Список кафедр»).

**Когда нужен запрос:** данные из нескольких таблиц или условия отбора. Пример: в таблице `Преподаватель` в поле `Кафедра` хранится **код**, а в отчёте нужно **название кафедры**. Для этого строим запрос с объединением `Преподаватель` и `Кафедра` и на его основе делаем отчёт «Преподаватели по кафедрам».

Дополнительный плюс запроса: изменив запрос (условие, сортировку), можно изменить содержимое отчёта, не пересоздавая его.

## 12. Как изменить порядок сортировки значений поля в готовом отчёте?

**Для динамического отчёта (создан в Конструкторе отчётов):**

1. В разделе «Отчёты» ПКМ по отчёту → **«Правка»**. Откроется конструктор.
2. Меню **Вид → Сортировка и группировка** (или кнопка на панели).
3. В окне сортировки в строке нужного поля (или добавить его в список) задать **порядок: по возрастанию / по убыванию**.
4. Сохранить (**Ctrl+S**) и нажать **«Выполнить отчёт»**, чтобы проверить.

**Альтернативный способ:** изменить порядок в **запросе**, на котором построен отчёт: в строке «Сортировка» запроса выбрать направление (`ORDER BY`), либо в свойствах отчёта изменить SQL-источник.

**Для статического отчёта** (снимок в виде документа): порядок строк менять нельзя. Нужно **заново создать** отчёт мастером с нужными параметрами сортировки (шаг 4) либо вручную отредактировать документ.

## 13. Когда нужно заполнять поля меток?

Заполнять (менять) метки нужно, когда **имя поля в таблице непонятно или неудобно для читателя отчёта**:

- в имени есть **подчёркивания**, сокращения, технические слова (`Номер_зачетки`, `Код_спец`);
- нужно дать **более полное и понятное название** (`ФИО` → «Фамилия, имя, отчество»);
- нужно, чтобы заголовок **помещался в узкий столбец** (короче, чем имя поля);
- отчёт предназначен для **официального документа** (деканат, кафедра), где нужны корректные заголовки.

**Можно не заполнять**, если имена полей уже понятны («Оценка», «Название») и подходят как заголовки.

Метки влияют только на **подписи в отчёте**, имена полей в БД остаются прежними.

## 14. Пример предметной области и параметры группирования

**Предметная область: деканат вуза.**

| Отчёт | Группировка по | Что получаем |
|---|---|---|
| Преподаватели | `Кафедра` | Список преподавателей под названием каждой кафедры |
| Студенты | `Специальность` | Студенты каждой специальности отдельно |
| Успеваемость | `Дисциплина` или `Студент` | Оценки по каждой дисциплине (или по каждому студенту) |
| Преподаватели | `Должность` | Профессора, доценты, ассистенты отдельными блоками |

**Другие предметные области:**

- **Магазин:** товары, группировка по категории; продажи — по дате или продавцу.
- **Библиотека:** книги, группировка по автору или жанру.
- **Склад:** остатки, группировка по поставщику.

Принцип выбора поля для группировки: оно должно содержать **повторяющиеся значения**, по которым записи естественно делятся на категории (кафедра, специальность, категория, месяц), а не уникальные (код, номер зачётки).

## 15. Почему в качестве разметки рекомендуется использовать табличный тип отчёта?

Табличная разметка предпочтительна для большинства отчётов, потому что:

1. **Компактность.** В одной строке одна запись, на странице умещается много записей, а значит, меньше страниц.
2. **Наглядность и сравнение.** Данные одного поля в столбце легко сравнивать (оклады, оценки, даты).
3. **Подписи один раз.** Метки печатаются в шапке столбцов один раз, а не повторяются у каждой записи, как в блочной разметке.
4. **Привычный вид документа.** Ведомости, списки, реестры оформляются таблицами.
5. **Хорошо сочетается с группировкой.** Под заголовком группы идёт таблица записей.
6. **Упрощает итоги.** Под столбцом удобно выводить сумму, среднее, количество.

Блочная («в столбцах») разметка уместна, когда записей мало, а полей много (карточка, анкета), поэтому табличная — разметка **по умолчанию**.

## 16. Чем статический отчёт отличается от динамического отчёта?

| | Статический отчёт | Динамический отчёт |
|---|---|---|
| Данные | **Снимок** на момент создания | **Берутся из БД** при каждом открытии |
| Актуальность | Не обновляется, устаревает при изменении БД | Всегда актуален |
| Хранение | Документ Writer (данные внутри документа) | Определение отчёта в БД, данные подгружаются из таблиц/запросов |
| Связь с БД | Нет после создания | Постоянная |
| Редактирование | Как обычный текстовый документ | Через конструктор отчётов (разметка, сортировка, группировка) |
| Когда выбирать | Нужно **зафиксировать** состояние данных на дату (архив, отправка) | Нужен **постоянно актуальный** отчёт |

**Пример:** «Список преподавателей» — динамический: при появлении нового преподавателя он появится в отчёте. «Ведомость на 01.09.2026» — статический, данные на эту дату не должны меняться.

Тип выбирается на последнем (шестом) шаге мастера.

## 17. Какие средства форматирования (редактирования) отчётов предоставляет LibreOffice Base?

Редактирование отчёта выполняется в **Конструкторе отчётов** (ПКМ по отчёту → **Правка**).

**Структура отчёта (разделы):** заголовок отчёта, верхний колонтитул страницы, заголовок группы, подробности, нижний колонтитул группы, нижний колонтитул страницы, нижний колонтитул отчёта. Разделы включаются и отключаются в меню **Правка → Разделы**.

**Элементы, которые можно добавить** (панель «Элементы управления отчёта»):

- **Метка** — статичный текст (заголовки, подписи);
- **Поле** — данные из источника;
- **Изображение** — логотип, рисунок;
- **Линия** и **прямоугольник** — рамки и разделители;
- **Форматированное поле / вычисляемое поле** — формулы и выражения;
- **Функции** (*Вид → Функции*): сумма, количество, среднее, минимум, максимум.

**Форматирование элементов (панель «Форматирование», окно свойств элемента):**

- шрифт, размер, начертание (жирный, курсив, подчёркивание), цвет текста;
- цвет **фона** и **границы** элемента;
- **выравнивание** текста (по левому краю, по центру, по правому);
- **формат чисел и дат** (денежный, дата, количество знаков после запятой);
- размеры и положение элемента, выравнивание нескольких элементов по краю или по размеру (меню **Формат**);
- **автоматический перенос** текста, высота строки.

**Свойства разделов:** высота, цвет фона, **видимость**, разрыв страницы перед/после раздела, «держать вместе».

**Дополнительно:**

- **Сортировка и группировка** (*Вид → Сортировка и группировка*): добавить, изменить уровни группировки, порядок сортировки, заголовок и колонтитул группы;
- **Условное форматирование** (например, выделить цветом оценки ниже 3);
- **Номера страниц и дата** (*Вставка → Номер страницы / Дата и время*), для этого используются колонтитулы;
- **Параметры страницы:** ориентация, поля, размер бумаги;
- **Предварительный просмотр** кнопкой «Выполнить отчёт» и экспорт в PDF, Writer, Calc.
