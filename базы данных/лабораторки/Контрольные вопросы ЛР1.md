# Лабораторная работа № 1. Контрольные вопросы

## База данных «Аренда недвижимости» (rental_estate)

Ответы подготовлены для PostgreSQL. В примерах используются таблицы Realtor, Client, Contract, Realty и District. Для примеров предполагаются связи Contract.ID_Client → Client.ID, Contract.ID_Realtor → Realtor.ID, Contract.ID_Realty → Realty.ID, Realty.ID_District → District.ID. Если в вашей физическойной схеме названия отличаются, замените их на фактические. В учебной работе может требоваться суффикс _FIO у имён БД и таблиц.

## 1. Сформулируйте принцип целостности сущностей

**Целостность сущностей** означает, что каждая строка таблицы должна однозначно идентифицироваться. Поэтому первичный ключ не может содержать NULL, а его значения должны быть уникальными. Ограничение PRIMARY KEY в PostgreSQL автоматически обеспечивает NOT NULL и UNIQUE.

Пример: каждому риэлтору присваивается уникальный идентификатор.

~~~sql
CREATE TABLE Realtor (
    ID SMALLSERIAL PRIMARY KEY,
    Fam VARCHAR(32) NOT NULL,
    Name VARCHAR(32) NOT NULL
);
~~~

Нельзя добавить две строки с одинаковым ID или строку без ID. Это позволяет адресовать конкретную запись в UPDATE и DELETE и ссылаться на неё из других таблиц.

## 2. Сформулируйте принцип целостности внешних ключей

**Целостность внешних ключей (ссылочная целостность)** требует, чтобы каждое ненулевое значение внешнего ключа дочерней таблицы ссылалось на существующую запись родительской таблицы.

Например, договор должен ссылаться на реально существующих клиента и риэлтора.

~~~sql
CREATE TABLE Contract (
    ID BIGSERIAL PRIMARY KEY,
    ID_Client INTEGER NOT NULL REFERENCES Client(ID),
    ID_Realtor SMALLINT NOT NULL REFERENCES Realtor(ID),
    Date_Begin DATE NOT NULL,
    Date_End DATE
);
~~~

Если клиента с указанным ID нет, PostgreSQL не позволит вставить такой договор. Внешний ключ может быть NULL, если связь необязательна и столбец не имеет NOT NULL. Поведение при удалении родительской строки задают ON DELETE RESTRICT, CASCADE или SET NULL.

## 3. Почему для атрибута внешнего ключа указывают только имя домена, а не полное описание домена?

Внешний ключ должен использовать тот же домен (тип и смысловой формат), что и ключ родительской таблицы. Полное повторное описание домена в дочерней таблице может привести к противоречиям: например, в родительской таблице идентификатор ограничен одним диапазоном, а в дочерней — другим. Правила идентификатора должны определяться в одном месте — в родительском отношении. В дочерней таблице указывают совместимый тип и ограничение REFERENCES.

~~~sql
CREATE TABLE Client (
    ID INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    Fam VARCHAR(32) NOT NULL
);

CREATE TABLE Contract (
    ID BIGSERIAL PRIMARY KEY,
    ID_Client INTEGER REFERENCES Client(ID)
);
~~~

Типы внешнего и родительского ключа должны быть совместимыми; лучше использовать один и тот же тип.

## 4. Какие команды SQL относятся к DML?

**DML (Data Manipulation Language)** — язык манипулирования данными. Основные команды:

- INSERT — добавление строк;
- UPDATE — изменение строк;
- DELETE — удаление строк;
- SELECT — выборка данных; в некоторых классификациях SELECT отдельно относят к DQL (Data Query Language).

Пример:

~~~sql
INSERT INTO Realtor (Fam, Name) VALUES ('Иванов', 'Иван');
UPDATE Realtor SET Name = 'Иван' WHERE ID = 1;
DELETE FROM Realtor WHERE ID = 1;
SELECT * FROM Realtor;
~~~

В учебной классификации часто перечисляют INSERT, UPDATE и DELETE как основные команды DML, а SELECT рассматривают отдельно.

## 5. Почему атрибут потенциального ключа должен иметь NOT NULL?

Потенциальный ключ должен однозначно идентифицировать каждую строку. NULL означает отсутствие или неизвестность значения и не может служить надёжным идентификатором. Если поле потенциального ключа допускает NULL, запись может остаться без значения, по которому её можно однозначно найти.

Пример: регистрационный номер недвижимости можно определить как обязательный и уникальный:

~~~sql
CREATE TABLE Realty (
    ID BIGSERIAL PRIMARY KEY,
    Registry_Number VARCHAR(30) NOT NULL UNIQUE
);
~~~

Если поле выбрано первичным ключом, PostgreSQL автоматически запрещает NULL.

## 6. Опишите упрощённый синтаксис INSERT

INSERT добавляет одну или несколько строк.

~~~sql
INSERT INTO имя_таблицы (столбец1, столбец2, ...)
VALUES (значение1, значение2, ...);
~~~

Несколько строк:

~~~sql
INSERT INTO Realtor (Fam, Name, Otch, Phone, Email)
VALUES
 ('Иванов', 'Иван', 'Петрович', '+7(927)-123-45-69', 'ivanov@example.com'),
 ('Сидорова', 'Анна', 'Игоревна', '+7(927)-123-45-70', 'sidorova@example.com');
~~~

Вставка результата запроса:

~~~sql
INSERT INTO Contract_Archive (ID, ID_Client, Date_Begin, Date_End)
SELECT ID, ID_Client, Date_Begin, Date_End
FROM Contract
WHERE Date_Begin < DATE '2025-01-01';
~~~

Если столбец генерируется автоматически или имеет DEFAULT, его можно не указывать. Явный список столбцов предпочтительнее, чем вставка без списка: запрос не зависит от физического порядка столбцов.

## 7. Опишите упрощённый синтаксис UPDATE

UPDATE изменяет значения столбцов в существующих строках.

~~~sql
UPDATE имя_таблицы
SET столбец1 = выражение1,
    столбец2 = выражение2
[WHERE условие];
~~~

Пример: исправить телефон риэлтора с ID = 3.

~~~sql
UPDATE Realtor
SET Phone = '+7(900)-111-22-33'
WHERE ID = 3;
~~~

Можно использовать вычисление:

~~~sql
UPDATE Realty
SET Price = Price * 1.05
WHERE ID = 12;
~~~

Если убрать WHERE, изменятся все строки таблицы. Перед изменением полезно выполнить SELECT с тем же условием.

## 8. Опишите упрощённый синтаксис DELETE

DELETE удаляет строки из таблицы.

~~~sql
DELETE FROM имя_таблицы
[WHERE условие];
~~~

Пример:

~~~sql
DELETE FROM Client
WHERE ID = 25;
~~~

Без WHERE будут удалены все строки таблицы, но сама таблица и её структура останутся. Перед удалением проверьте условие запросом SELECT. Если на запись ссылаются внешние ключи, удаление может быть запрещено или выполнено согласно ON DELETE.

## 9. Как создать базу данных в оболочке psql?

1. Открыть SQL Shell (psql) и подключиться к серверу PostgreSQL.
2. Выполнить:

~~~sql
CREATE DATABASE rental_estate;
~~~

3. Подключиться к базе:

~~~text
\c rental_estate
~~~

Проверить подключение можно командой \conninfo. Если по заданию требуется суффикс, например, используйте CREATE DATABASE rental_estate_ivanov.

## 10. Как создать таблицу в psql?

Для создания таблицы используется DDL-команда CREATE TABLE. В ней указываются столбцы, типы и ограничения.

~~~sql
CREATE TABLE Realtor (
    ID SMALLSERIAL PRIMARY KEY,
    Fam VARCHAR(32) NOT NULL,
    Name VARCHAR(32) NOT NULL,
    Otch VARCHAR(32),
    Phone CHAR(17),
    Email VARCHAR(64)
);
~~~

SMALLSERIAL создаёт целочисленный столбец с автоматически генерируемым значением; PRIMARY KEY задаёт первичный ключ; VARCHAR(32) — строка переменной длины до 32 символов; NOT NULL запрещает пропуск значения. Структуру можно посмотреть в psql командой \d Realtor, список таблиц — \dt.

## 11. Как создать внешний ключ в psql?

Внешний ключ задают при создании таблицы или позднее через ALTER TABLE.

~~~sql
CREATE TABLE Contract (
    ID BIGSERIAL PRIMARY KEY,
    ID_Client INTEGER NOT NULL,
    ID_Realtor SMALLINT NOT NULL,
    Date_Begin DATE NOT NULL,
    CONSTRAINT fk_contract_client
        FOREIGN KEY (ID_Client) REFERENCES Client(ID),
    CONSTRAINT fk_contract_realtor
        FOREIGN KEY (ID_Realtor) REFERENCES Realtor(ID)
);
~~~

Позднее:

~~~sql
ALTER TABLE Contract
ADD CONSTRAINT fk_contract_client
FOREIGN KEY (ID_Client) REFERENCES Client(ID);
~~~

Типы столбцов должны быть совместимыми с типами родительских ключей. Имя ограничения после CONSTRAINT выбирает разработчик.

## 12. Как удалить не все строки, а только заданные?

Нужно указать WHERE с условием отбора.

~~~sql
DELETE FROM Contract
WHERE ID = 105;
~~~

Для проверки сначала выполните:

~~~sql
SELECT *
FROM Contract
WHERE ID = 105;
~~~

Без WHERE DELETE удалит все строки. Условие, которое всегда истинно, приведёт к тому же результату.

## 13. Почему в современных СУБД невозможно повторение проблемы Y2K?

Проблема Y2K возникла в старых системах, где год хранили двумя цифрами: 99 могло означать 1999, а 00 — ошибочно трактоваться как 1900. Современные СУБД предоставляют типы DATE, TIMESTAMP и TIMESTAMPTZ с полноценным представлением года, поэтому обычное использование этих типов не создаёт такой неоднозначности.

~~~sql
CREATE TABLE Contract (
    ID BIGSERIAL PRIMARY KEY,
    Date_Begin DATE NOT NULL
);

INSERT INTO Contract (Date_Begin)
VALUES (DATE '2026-11-18');
~~~

Это не означает, что любые программы полностью защищены от ошибок дат: разработчик всё ещё может самостоятельно хранить год двумя цифрами, неверно разбирать текстовую дату или ошибаться с часовыми поясами.

## 14. Приведите пример подзапроса в UPDATE

Подзапрос может вычислить значение, которое присваивается столбцу в SET. Скалярный подзапрос должен вернуть не более одной строки и одного столбца.

~~~sql
UPDATE Contract
SET ID_Client = (
    SELECT ID
    FROM Client
    WHERE Fam = 'Иванов'
      AND Name = 'Пётр'
)
WHERE ID = 562;
~~~

Внутренний SELECT находит ID клиента, внешний UPDATE записывает его в договор № 562. Если по ФИО найдётся несколько клиентов, PostgreSQL выдаст ошибку, потому что скалярный подзапрос вернул больше одной строки.

## 15. Приведите пример использования DELETE

Удалим тестовый договор с известным идентификатором:

~~~sql
DELETE FROM Contract
WHERE ID = 562;
~~~

Пример более сложного условия:

~~~sql
DELETE FROM Contract
WHERE Date_Begin < DATE '2010-01-01'
  AND Date_End IS NOT NULL;
~~~

Второй запрос удалит завершённые договоры, начавшиеся до 2010 года. Перед выполнением нужно проверить выбранные записи и ограничения внешних ключей.

## 16. Приведите пример использования INSERT

Добавим риэлтора. ID не указываем, поскольку он генерируется автоматически.

~~~sql
INSERT INTO Realtor (Fam, Name, Otch, Phone, Email)
VALUES ('Сидоров', 'Александр', 'Игоревич',
        '+7(927)-123-45-69', 'sidorov@example.com');
~~~

Добавим договор для существующих клиента и риэлтора:

~~~sql
INSERT INTO Contract (ID_Client, ID_Realtor, Date_Begin, Date_End)
VALUES (4, 2, DATE '2026-06-01', DATE '2026-12-01');
~~~

Второй запрос сработает, только если клиент ID=4 и риэлтор ID=2 существуют и выполнены остальные ограничения таблицы.

## 17. Какие команды SQL относятся к DDL?

**DDL (Data Definition Language)** — язык определения данных. Он управляет структурой БД и её объектов.

- CREATE — создать объект;
- ALTER — изменить структуру объекта;
- DROP — удалить объект;
- TRUNCATE — удалить все строки таблицы, сохранив саму таблицу (в PostgreSQL эту команду обычно относят к DDL);
- COMMENT — добавить комментарий к объекту.

Примеры:

~~~sql
CREATE TABLE District (
    ID SMALLSERIAL PRIMARY KEY,
    Name VARCHAR(50) NOT NULL
);

ALTER TABLE District ADD COLUMN Rating NUMERIC(3, 1);
COMMENT ON TABLE District IS 'Районы города';
~~~

DROP TABLE удаляет таблицу целиком вместе со структурой, а DELETE FROM District удаляет строки, сохраняя таблицу.

## 18. Для чего используются последовательные типы данных?

SMALLSERIAL, SERIAL и BIGSERIAL — псевдотипы PostgreSQL для создания целочисленного столбца с автоматически генерируемым значением из последовательности (SEQUENCE). Обычно их применяют для первичных ключей.

- SMALLSERIAL — небольшой диапазон (2 байта);
- SERIAL — обычный целочисленный диапазон (4 байта);
- BIGSERIAL — большой диапазон (8 байт).

~~~sql
CREATE TABLE District (
    ID SMALLSERIAL PRIMARY KEY,
    Name VARCHAR(50) NOT NULL
);

INSERT INTO District (Name)
VALUES ('Центральный'), ('Северный');
~~~

PostgreSQL автоматически присвоит ID. Сам по себе SERIAL не гарантирует уникальность: для этого требуется PRIMARY KEY или UNIQUE. Современная альтернатива — ID INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY.

## 19. Когда использовать VARCHAR(n), а когда CHAR(n)?

VARCHAR(n) предназначен для строк переменной длины с заданным максимальным количеством символов. CHAR(n) — для строк фиксированной длины; короткие значения дополняются пробелами.

Примеры: фамилия, имя и e-mail обычно хранятся в VARCHAR; телефон можно хранить в CHAR(17), если формат строго фиксирован.

~~~sql
CREATE TABLE Realtor (
    Fam VARCHAR(32) NOT NULL,
    Name VARCHAR(32) NOT NULL,
    Phone CHAR(17)
);
~~~

Для большинства обычных текстовых полей удобнее VARCHAR или TEXT. CHAR стоит выбирать, когда фиксированная длина действительно является правилом предметной области.

## 20. Когда использовать TEXT?

TEXT используют для строк переменной длины, когда нет необходимости задавать небольшой предел на уровне типа. Например, для адреса объекта, описания недвижимости или комментария к договору.

~~~sql
CREATE TABLE Realty (
    ID BIGSERIAL PRIMARY KEY,
    Address TEXT NOT NULL,
    Description TEXT
);
~~~

В PostgreSQL TEXT и VARCHAR без ограничения длины практически эквивалентны по возможностям и производительности. VARCHAR(n) полезен, если максимальная длина — реальное требование предметной области; TEXT — если длина заранее не ограничивается небольшим числом.

## Краткая памятка

| Конструкция | Назначение |
|---|---|
| PRIMARY KEY | Уникально идентифицирует строку, запрещает NULL |
| FOREIGN KEY / REFERENCES | Проверяет существование родительской записи |
| NOT NULL | Запрещает отсутствие значения |
| UNIQUE | Запрещает повтор значений |
| CHECK | Проверяет логическое условие |
| INSERT | Добавляет строки |
| UPDATE | Изменяет строки |
| DELETE | Удаляет строки |
| CREATE / ALTER / DROP | Управляют структурой объектов |

Перед UPDATE или DELETE проверяйте условие через SELECT. Для важных изменений используйте транзакцию BEGIN, COMMIT и ROLLBACK.
