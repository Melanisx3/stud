# Лабораторная работа № 2. Простые запросы и типы соединений

## Контрольные вопросы с примерами для БД «Аренда недвижимости» (rental_estate)

Примеры написаны для PostgreSQL. Используются таблицы Client, Realtor, Contract, Realty, District и Realty_Type. Предполагаемые связи: Contract.ID_Client → Client.ID; Contract.ID_Realtor → Realtor.ID; Contract.ID_Realty → Realty.ID; Realty.ID_District → District.ID; Realty.ID_Type → Realty_Type.ID. Если физическая схема использует другие имена (например, Tenant вместо Client), замените их на фактические. Если в Contract нет ID_Realty, используйте реальный FK договора на объект недвижимости.

## 1. Приведите базовый синтаксис оператора SELECT

SELECT извлекает данные из одной или нескольких таблиц и возвращает результирующий набор. Сам по себе запрос не изменяет исходные таблицы.

~~~sql
SELECT [DISTINCT] список_столбцов
FROM источник_данных
[WHERE условие]
[GROUP BY столбцы_группировки]
[HAVING условие_для_групп]
[ORDER BY столбцы_сортировки [ASC | DESC]];
~~~

Назначение частей:
- SELECT — какие столбцы или выражения вывести;
- DISTINCT — убрать повторяющиеся строки результата;
- FROM — источник данных;
- WHERE — фильтр исходных строк;
- GROUP BY — объединение строк в группы;
- HAVING — фильтр сформированных групп;
- ORDER BY — сортировка результата.

Пример: список клиентов:

~~~sql
SELECT ID, Fam, Name, Phone
FROM Client
ORDER BY Fam ASC, Name ASC;
~~~

Пример: договоры, начавшиеся в 2026 году:

~~~sql
SELECT ID, ID_Client, Date_Begin, Date_End
FROM Contract
WHERE Date_Begin >= DATE '2026-01-01'
  AND Date_Begin < DATE '2027-01-01'
ORDER BY Date_Begin;
~~~

## 2. Для чего используется ORDER BY?

ORDER BY задаёт порядок строк результата. Без ORDER BY SQL не гарантирует порядок вывода.

- ASC — по возрастанию (значение по умолчанию);
- DESC — по убыванию.

Можно сортировать по нескольким столбцам: сначала по первому, при совпадении — по следующему.

~~~sql
SELECT ID, Date_Begin, Date_End
FROM Contract
ORDER BY Date_Begin ASC;
~~~

Клиенты по фамилии и имени:

~~~sql
SELECT Fam, Name, Phone
FROM Client
ORDER BY Fam ASC, Name ASC;
~~~

В PostgreSQL положение NULL можно задать явно: NULLS FIRST или NULLS LAST.

~~~sql
SELECT ID, Date_End
FROM Contract
ORDER BY Date_End ASC NULLS LAST;
~~~

## 3. Для чего используется GROUP BY?

GROUP BY объединяет строки с одинаковыми значениями указанных столбцов в группы. Обычно применяется вместе с агрегатными функциями COUNT, SUM, AVG, MIN и MAX.

Пример: количество договоров у каждого риэлтора:

~~~sql
SELECT ID_Realtor, COUNT(*) AS contract_count
FROM Contract
GROUP BY ID_Realtor
ORDER BY contract_count DESC;
~~~

Пример: средняя стоимость недвижимости по районам:

~~~sql
SELECT d.ID, d.Name AS district,
       AVG(r.Price) AS average_price
FROM Realty AS r
JOIN District AS d ON d.ID = r.ID_District
GROUP BY d.ID, d.Name
ORDER BY average_price DESC;
~~~

В PostgreSQL каждый столбец в SELECT, который не находится внутри агрегатной функции, должен быть указан в GROUP BY либо функционально зависеть от сгруппированного ключа.

## 4. Для чего используется HAVING?

HAVING фильтрует группы, уже сформированные GROUP BY. WHERE фильтрует отдельные строки до группировки; HAVING обычно содержит агрегатные условия.

Пример: риэлторы, у которых больше двух договоров:

~~~sql
SELECT ID_Realtor, COUNT(*) AS contract_count
FROM Contract
GROUP BY ID_Realtor
HAVING COUNT(*) > 2
ORDER BY contract_count DESC;
~~~

В примере ниже WHERE сначала оставляет договоры, начавшиеся в 2026 году; GROUP BY считает их по риэлторам; HAVING оставляет группы, в которых таких договоров не меньше двух.

~~~sql
SELECT ID_Realtor, COUNT(*) AS active_contracts
FROM Contract
WHERE Date_Begin >= DATE '2026-01-01'
GROUP BY ID_Realtor
HAVING COUNT(*) >= 2;
~~~

## 5. Для чего используется UNION?

UNION объединяет результаты двух или нескольких SELECT в один набор. Запросы должны возвращать одинаковое количество столбцов, а типы соответствующих столбцов должны быть совместимы.

UNION удаляет повторяющиеся строки. UNION ALL сохраняет повторы и обычно требует меньше вычислений.

Пример: общий список клиентов и риэлторов с указанием роли:

~~~sql
SELECT Fam AS surname, 'Клиент' AS role
FROM Client
UNION
SELECT Fam AS surname, 'Риэлтор' AS role
FROM Realtor
ORDER BY surname, role;
~~~

Строки с одинаковой фамилией, но разными ролями не являются дубликатами, поскольку второй столбец отличается.

## 6. Какие операторы сравнения используются в предикате WHERE?

Основные операторы:

| Оператор | Значение |
|---|---|
| = | равно |
| <> или != | не равно |
| > | больше |
| < | меньше |
| >= | больше или равно |
| <= | меньше или равно |

Также применяются специальные предикаты:
- BETWEEN ... AND ... — значение внутри диапазона, включая границы;
- IN (...) — значение входит в список;
- LIKE / ILIKE — соответствие шаблону (% — любое количество символов, _ — один символ; ILIKE в PostgreSQL не учитывает регистр);
- IS NULL / IS NOT NULL — проверка отсутствующего значения;
- EXISTS — проверка, вернул ли подзапрос хотя бы одну строку;
- ANY / SOME и ALL — сравнение со значениями подзапроса.

~~~sql
-- Цена в заданном диапазоне
SELECT * FROM Realty
WHERE Price BETWEEN 30000 AND 70000;

-- Недвижимость выбранных типов
SELECT * FROM Realty
WHERE ID_Type IN (1, 3);

-- Адреса, содержащие слово «улица»
SELECT * FROM Realty
WHERE Address ILIKE '%улица%';

-- Договоры без даты окончания
SELECT * FROM Contract
WHERE Date_End IS NULL;
~~~

SQL использует трёхзначную логику: TRUE, FALSE или UNKNOWN. Сравнение с NULL обычно даёт UNKNOWN, поэтому для проверки отсутствующего значения нужно писать IS NULL, а не = NULL.

## 7. Приведите пример CROSS JOIN двух таблиц

CROSS JOIN — перекрёстное соединение (декартово произведение). Каждая строка первой таблицы сочетается с каждой строкой второй. Если в первой таблице 4 строки, а во второй 3, результат содержит 4 × 3 = 12 строк.

Пример: все комбинации районов и типов недвижимости:

~~~sql
SELECT d.Name AS district,
       t.Name AS property_type
FROM District AS d
CROSS JOIN Realty_Type AS t
ORDER BY d.Name, t.Name;
~~~

Такой запрос подходит, например, для матрицы «район × тип недвижимости». Он не проверяет связь по внешнему ключу и намеренно создаёт все возможные комбинации.

## 8. Приведите пример INNER JOIN двух таблиц

INNER JOIN возвращает только сочетания строк, для которых условие соединения истинно. Строки без соответствующей записи во второй таблице не попадают в результат.

Пример: договоры и фамилии клиентов:

~~~sql
SELECT c.ID AS contract_id,
       cl.Fam, cl.Name, c.Date_Begin
FROM Contract AS c
INNER JOIN Client AS cl
    ON cl.ID = c.ID_Client
ORDER BY c.Date_Begin;
~~~

Если соответствующий клиент отсутствует, строка договора не будет показана. В PostgreSQL JOIN без слова INNER эквивалентен INNER JOIN.

## 9. Приведите пример LEFT JOIN

LEFT JOIN возвращает все строки левой таблицы и совпавшие строки правой таблицы. Если совпадения нет, столбцы правой таблицы заполняются NULL.

Пример: все клиенты, в том числе без договоров:

~~~sql
SELECT cl.ID, cl.Fam, cl.Name,
       c.ID AS contract_id
FROM Client AS cl
LEFT JOIN Contract AS c
    ON c.ID_Client = cl.ID
ORDER BY cl.Fam, cl.Name;
~~~

Чтобы найти только клиентов без договоров:

~~~sql
SELECT cl.ID, cl.Fam, cl.Name
FROM Client AS cl
LEFT JOIN Contract AS c
    ON c.ID_Client = cl.ID
WHERE c.ID IS NULL;
~~~

## 10. Приведите пример RIGHT JOIN

RIGHT JOIN сохраняет все строки правой таблицы, даже если соответствующей строки в левой таблице нет. Для отсутствующей пары столбцы левой таблицы будут NULL.

~~~sql
SELECT c.ID AS contract_id,
       c.Date_Begin,
       cl.Fam, cl.Name
FROM Client AS cl
RIGHT JOIN Contract AS c
    ON cl.ID = c.ID_Client
ORDER BY c.Date_Begin;
~~~

Все договоры останутся в результате. Если клиента нет, его поля будут NULL. Часто такой запрос удобнее переписать через LEFT JOIN, поменяв таблицы местами:

~~~sql
SELECT c.ID AS contract_id,
       c.Date_Begin,
       cl.Fam, cl.Name
FROM Contract AS c
LEFT JOIN Client AS cl
    ON cl.ID = c.ID_Client;
~~~

Эти запросы логически эквивалентны.

## 11. Приведите пример соединения по указываемым столбцам (USING)

USING применяется, когда обе таблицы соединяются по столбцу с одинаковым именем. Имя общего столбца указывается один раз.

Пример возможен, если PK района и FK недвижимости действительно называются одинаково:

~~~sql
SELECT ID_District, d.Name, r.Address
FROM Realty AS r
JOIN District AS d USING (ID_District);
~~~

Если PK называется ID, а FK — ID_District, USING применить нельзя; используйте ON:

~~~sql
SELECT d.ID, d.Name, r.Address
FROM Realty AS r
JOIN District AS d ON d.ID = r.ID_District;
~~~

USING объединяет одноимённый столбец в результирующем наборе, поэтому он не выводится дважды.

## 12. Приведите пример соединения по предикату (ON)

ON задаёт условие, по которому сопоставляются строки двух таблиц. Оно может включать равенство ключей и дополнительные логические выражения.

~~~sql
SELECT c.ID AS contract_id,
       r.Address, r.Price
FROM Contract AS c
JOIN Realty AS r
    ON r.ID = c.ID_Realty;
~~~

Дополнительное условие в ON:

~~~sql
SELECT c.ID, r.Address, r.Price
FROM Contract AS c
JOIN Realty AS r
    ON r.ID = c.ID_Realty
   AND r.Price > 50000;
~~~

ON определяет пары строк. WHERE фильтрует полученный результат. Для внешних соединений перенос условия между ON и WHERE может изменить результат.

## 13. Приведите пример UNION-объединения

UNION объединяет результаты запросов и удаляет полностью совпадающие строки.

~~~sql
SELECT Fam, Name, 'Клиент' AS role
FROM Client
UNION
SELECT Fam, Name, 'Риэлтор' AS role
FROM Realtor
ORDER BY Fam, Name;
~~~

Требования: одинаковое количество столбцов, совместимые типы соответствующих столбцов и одинаковый смысловой порядок столбцов. Для сохранения повторов применяют UNION ALL.

## 14. Приведите пример INTERSECT-объединения

INTERSECT возвращает строки, которые присутствуют в обоих результирующих наборах. По умолчанию дубликаты удаляются.

Пример: фамилии, встречающиеся и среди клиентов, и среди риэлторов:

~~~sql
SELECT Fam FROM Client
INTERSECT
SELECT Fam FROM Realtor;
~~~

Сравниваются все столбцы результирующей строки. Если SELECT возвращает несколько столбцов, совпасть должны все соответствующие значения.

## 15. Приведите пример EXCEPT-объединения

EXCEPT возвращает строки, которые есть в результате первого SELECT, но отсутствуют во втором. Это разность множеств. Порядок запросов важен: A EXCEPT B не равно B EXCEPT A.

Пример: фамилии клиентов, которые не встречаются среди риэлторов:

~~~sql
SELECT Fam FROM Client
EXCEPT
SELECT Fam FROM Realtor;
~~~

В PostgreSQL используется EXCEPT; в некоторых других СУБД применяется MINUS.

## 16. Какие реляционные операции лежат в основе оператора SELECT?

Основные операции реляционной алгебры:
- **проекция** — выбор отдельных атрибутов (столбцов), соответствует списку в SELECT;
- **селекция** — отбор кортежей по условию, соответствует WHERE;
- **декартово произведение** — сочетание каждой строки с каждой, соответствует CROSS JOIN;
- **соединение** — объединение связанных строк отношений, соответствует JOIN ... ON;
- **переименование** — задание псевдонимов таблиц и столбцов через AS.

SQL также поддерживает группировку, агрегирование и операции над множествами. Важно: классическое отношение является множеством без дубликатов, а SQL допускает повторяющиеся строки, если не указано DISTINCT.

## 17. Какая реляционная операция лежит в основе UNION?

В основе UNION лежит операция **объединения множеств**. Она формирует строки, принадлежащие первому результату, второму или обоим. При обычном UNION совпадающая строка включается один раз. Для объединения запросы должны быть совместимы по числу и типам столбцов.

## 18. Какая реляционная операция соответствует EXCEPT и как она работает?

EXCEPT соответствует операции **разности множеств**: из строк первого результата исключаются строки, которые присутствуют во втором.

Пример: районы, в которых есть объекты недвижимости, но нет договоров по этим объектам:

~~~sql
SELECT ID_District
FROM Realty
EXCEPT
SELECT r.ID_District
FROM Realty AS r
JOIN Contract AS c ON c.ID_Realty = r.ID;
~~~

Этот пример возвращает идентификаторы районов. Более наглядный вариант с названиями:

~~~sql
SELECT d.ID, d.Name
FROM District AS d
WHERE EXISTS (
    SELECT 1
    FROM Realty AS r
    WHERE r.ID_District = d.ID
)
AND NOT EXISTS (
    SELECT 1
    FROM Realty AS r
    JOIN Contract AS c ON c.ID_Realty = r.ID
    WHERE r.ID_District = d.ID
);
~~~

## Дополнительные запросы для подготовки к защите

### Все договоры с клиентом, риэлтором и адресом объекта

~~~sql
SELECT c.ID AS contract_id,
       cl.Fam AS client_surname,
       cl.Name AS client_name,
       re.Fam AS realtor_surname,
       re.Name AS realtor_name,
       r.Address,
       c.Date_Begin,
       c.Date_End
FROM Contract AS c
JOIN Client AS cl ON cl.ID = c.ID_Client
JOIN Realtor AS re ON re.ID = c.ID_Realtor
JOIN Realty AS r ON r.ID = c.ID_Realty
ORDER BY c.Date_Begin DESC;
~~~

### Риэлторы, заключившие договоры по объектам в выбранном районе

~~~sql
SELECT DISTINCT re.ID, re.Fam, re.Name
FROM Realtor AS re
JOIN Contract AS c ON c.ID_Realtor = re.ID
JOIN Realty AS r ON r.ID = c.ID_Realty
JOIN District AS d ON d.ID = r.ID_District
WHERE d.Name = 'Центральный'
ORDER BY re.Fam, re.Name;
~~~

### Районы и количество объектов в каждом районе, включая пустые

~~~sql
SELECT d.ID, d.Name,
       COUNT(r.ID) AS property_count
FROM District AS d
LEFT JOIN Realty AS r ON r.ID_District = d.ID
GROUP BY d.ID, d.Name
ORDER BY property_count DESC, d.Name;
~~~

Здесь используется COUNT(r.ID), а не COUNT(*): при LEFT JOIN район без объектов всё равно образует одну строку с NULL в полях недвижимости. COUNT(r.ID) вернёт 0, а COUNT(*) — 1.

## Главное различие соединений

| Оператор | Какие строки попадают в результат |
|---|---|
| CROSS JOIN | Все возможные пары строк |
| INNER JOIN | Только пары с совпадением по условию |
| LEFT JOIN | Все строки левой таблицы + совпадения справа |
| RIGHT JOIN | Все строки правой таблицы + совпадения слева |
| FULL JOIN | Все строки обеих таблиц; где пары нет — NULL |
| JOIN ... USING | Соединение по одноимённым столбцам |
| JOIN ... ON | Соединение по явно заданному условию |

## Упрощённый логический порядок обработки SELECT

1. FROM и JOIN — формирование источника строк;
2. WHERE — фильтрация отдельных строк;
3. GROUP BY — формирование групп;
4. HAVING — фильтрация групп;
5. SELECT — вычисление выводимых выражений;
6. DISTINCT — устранение повторов;
7. ORDER BY — сортировка;
8. LIMIT / OFFSET — ограничение выдачи.

Это объясняет, почему агрегатные условия обычно размещают в HAVING, а не в WHERE.
