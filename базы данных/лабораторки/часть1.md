## Основные понятия информационных систем и реляционных баз данных

## 1. Дайте определение информационной системы

**Информационная система (ИС)** — это организационно-техническая система, предназначенная для **сбора, хранения, обработки, поиска, передачи и предоставления информации** пользователям для решения определённых задач.

Проще говоря, информационная система объединяет:

- данные, с которыми работает организация;
- программное обеспечение для работы с этими данными;
- технические средства (компьютеры, серверы, сети и т. д.);
- людей, которые вводят, изменяют и используют информацию;
- правила и процедуры работы с информацией.

### Пример

В университете информационной системой может быть система учёта студентов. В ней хранятся сведения о студентах, группах, дисциплинах, преподавателях и оценках. Пользователь может найти студента, посмотреть его группу, получить оценки или сформировать отчёт.

### Как это связано с БД

В большинстве современных ИС значительная часть информации хранится в **базе данных**. Поэтому база данных является одной из важнейших частей информационной системы. Её часто называют **фундаментом ИС**: если данные организованы плохо, то и программы, работающие с ними, будут работать неудобно или ненадёжно. Такой подход также используется в учебной литературе по проектированию БД. citeturn199637search0turn199637search22

## 2. Что означает термин «ИС БД»

Термин **«ИС БД»** обычно понимают как **информационная система на основе базы данных**, то есть информационная система, в которой основное хранение и обработка информации организованы с помощью базы данных.

В такой системе можно выделить несколько основных частей:

1. **База данных (БД)** — сами структурированные данные.
2. **СУБД** — программное средство, которое позволяет создавать БД, хранить данные, изменять их, выполнять запросы, обеспечивать целостность и другие операции.
3. **Прикладная часть** — формы, отчёты, программы и другие средства, через которые пользователь работает с данными.
4. **Пользователи** — люди или другие системы, которые используют информацию.

### Главное различие БД и СУБД

- **БД** — это данные и их структура.
- **СУБД** — это программный комплекс для управления этими данными.

Например, если представить электронный архив документов, то сами сведения об этих документах являются **данными БД**, а программа, которая позволяет добавлять документы, искать их и изменять записи, относится к **СУБД/программному обеспечению работы с БД**.

В LibreOffice Base файл базы данных содержит объекты вроде таблиц, запросов, форм и отчётов, а сама Base может работать как интерфейс к встроенной или внешней реляционной БД. citeturn183987search1

## 3. Что такое «фундамент» ИС БД?

**Фундаментом информационной системы на основе БД является база данных.**

Такую аналогию используют потому, что база данных определяет, **какая информация существует в системе, как она организована и какие связи между данными существуют**.

### Почему именно БД — фундамент

Представим систему университета. В БД могут храниться:

- преподаватели;
- студенты;
- группы;
- дисциплины;
- оценки;
- расписание.

Из этих данных затем строятся формы, запросы, отчёты и прикладные функции. Если структура БД неправильная, то исправление ошибок затронет и программы, которые используют эту структуру.

Поэтому при проектировании ИС сначала очень тщательно проектируют данные: определяют объекты, атрибуты, ключи и связи.

**Итог:**

> **Фундамент ИС — база данных, потому что именно она хранит основную информацию и определяет основу для работы прикладных программ.**

В учебных материалах по информационным системам БД также непосредственно называется фундаментом информационной системы. citeturn199637search24turn199637search27

## 4. Что такое «здание» ИС БД?

Если БД — это **фундамент**, то условным **«зданием»** являются программные компоненты и пользовательские средства, построенные поверх этого фундамента: прикладные программы, интерфейсы, формы, отчёты, алгоритмы обработки и бизнес-логика.

Можно представить схему так:

```text
Пользователь
     ↓
Интерфейс / формы / приложение
     ↓
Запросы и логика обработки
     ↓
СУБД
     ↓
БАЗА ДАННЫХ
```

То есть:

- **БД** — фундамент;
- **СУБД** — средство управления фундаментом и доступом к данным;
- **прикладное программное обеспечение** — основная часть «здания», с которой работает пользователь.

### Почему эта аналогия полезна

Хорошо спроектированную БД можно использовать для нескольких приложений. Например, одна БД университета может использоваться:

- деканатом;
- преподавателями;
- студентами;
- бухгалтерией;
- системой отчётности.

Таким образом, различные «этажи» и «комнаты» приложения могут опираться на одну информационную основу.

## 5. Приведите примеры «локальных» (офисных) СУБД

**Локальные (офисные) СУБД** — это СУБД, которые рассчитаны прежде всего на работу с БД непосредственно на компьютере пользователя и часто используются для небольших или учебных информационных систем.

Примеры:

1. **Microsoft Access** — известная офисная СУБД из пакета Microsoft Office.
2. **LibreOffice Base** — компонент LibreOffice для создания и использования баз данных.
3. **OpenOffice Base** — аналогичный компонент в Apache OpenOffice.
4. **dBASE** — исторически известная СУБД для локальной работы с табличными данными.
5. **FileMaker** — настольная СУБД с развитым визуальным интерфейсом.

### Важно

LibreOffice Base не следует понимать только как самостоятельный «движок БД». Base может работать с различными источниками данных и в том числе подключаться к внешним реляционным СУБД, например MySQL или Oracle. citeturn183987search1

## 6. Дайте определение домена

**Домен** — это множество допустимых значений, которые может принимать атрибут, вместе с правилами и ограничениями, определяющими эти значения.

Проще говоря, домен отвечает на вопрос:

> **«Какие значения вообще разрешено записывать в данное поле?»**

### Из чего состоит описание домена

При описании домена обычно указывают:

- тип данных;
- допустимый диапазон или множество значений;
- формат записи;
- дополнительные ограничения.

### Пример

Если поле хранит возраст студента, можно задать домен:

- тип: целое число;
- допустимые значения: например, от 16 до 100.

Тогда значения `20` и `35` допустимы, а `-5` или строка `Иван` — нет.

### Домен и поле — не одно и то же

Домен задаёт **множество допустимых значений**, а поле (атрибут) использует этот домен для хранения конкретного значения в конкретной записи.

Например:

```text
Домен:        целые номера от 1 до 999999
Атрибут:      ТабельныйНомер
Значение:     15427
```

## 7. Опишите домен «Табельный номер» преподавателя

**Табельный номер преподавателя** — это идентификатор, присваиваемый преподавателю внутри организации. Его значение должно однозначно обозначать сотрудника в рамках принятой системы учёта.

Один из возможных вариантов описания домена:

| Свойство | Описание |
|---|---|
| Назначение | Уникальная идентификация преподавателя |
| Тип | Целое число или строка фиксированного формата — в зависимости от правил организации |
| Уникальность | Да, для каждого преподавателя номер должен быть уникальным |
| Пустое значение | Обычно не допускается |
| Диапазон | Например, положительные целые значения; конкретный диапазон определяется организацией |
| Дополнительные ограничения | Не должно быть двух преподавателей с одним табельным номером |

### Почему иногда лучше использовать строковый тип

Хотя табельный номер часто выглядит как число, на практике он может быть именно **кодом**, а не числом для математических расчётов.

Например, если номера могут иметь ведущие нули:

```text
00125
00126
00127
```

при числовом типе нули будут потеряны, а при строковом типе сохранятся.

Поэтому окончательный выбор типа зависит от принятого формата табельных номеров.

### В БД

Если табельный номер гарантированно уникален, его можно использовать как **потенциальный ключ**, а при выборе одного из потенциальных ключей — как **первичный ключ** таблицы преподавателей.

## 8. Опишите домен «Номер зачетки»

**Номер зачётки** — это идентификатор учебной книжки студента, который используется для однозначной идентификации соответствующего студента в рамках системы учёта.

Возможное описание домена:

| Свойство | Описание |
|---|---|
| Назначение | Идентификация студента по номеру зачётной книжки |
| Тип | Число или строка — в зависимости от формата номера |
| Уникальность | Обычно каждый действующий номер должен быть уникальным |
| Пустое значение | Обычно не допускается |
| Формат | Определяется правилами учебного заведения |
| Ограничения | Значение не должно дублироваться и должно соответствовать установленному формату |

### Пример

Допустимые значения могут иметь вид:

```text
241001
241002
241003
```

или, если в номере присутствуют буквы и разделители:

```text
ИС-24-001
ИС-24-002
```

Во втором случае строковый тип данных очевидно предпочтительнее числового.

### Важная мысль

Домен описывает не только тип, но и **смысловые ограничения**. Поэтому домен «Номер зачётки» — это не просто «целое число», а множество значений, которые могут корректно использоваться как номера зачётных книжек.

## 9. Чем атрибут реляционного отношения отличается от домена?

Разница заключается в следующем:

- **Домен** определяет множество допустимых значений.
- **Атрибут** — это именованное свойство (столбец) конкретного реляционного отношения, значения которого берутся из определённого домена.

### Пример

Пусть есть таблица преподавателей:

| ТабельныйНомер | ФИО |
|---:|---|
| 101 | Иванов И.И. |
| 102 | Петров П.П. |
| 103 | Сидорова А.А. |

Здесь:

- `ТабельныйНомер` — **атрибут**;
- `101`, `102`, `103` — конкретные **значения атрибута**;
- множество всех допустимых табельных номеров — **домен**.

### Ещё проще

Можно запомнить так:

> **Домен отвечает на вопрос «какие значения разрешены?», а атрибут — «какое именованное поле использует эти значения?».**

Например:

```text
Домен: положительные номера преподавателей
        ↓
Атрибут: ТабельныйНомер
        ↓
Конкретное значение: 102
```

Таким образом, атрибут — часть структуры отношения, а домен — ограничение на множество значений, которые может принимать этот атрибут.

## 10. Дайте определение реляционного отношения

**Реляционное отношение** — это математическое понятие, лежащее в основе реляционной модели данных. Практически его можно рассматривать как множество кортежей (записей), где каждый кортеж содержит значения атрибутов из соответствующих доменов.

В табличном представлении:

- отношение соответствует таблице;
- атрибут соответствует столбцу;
- кортеж соответствует строке;
- значение атрибута — конкретной ячейке.

### Пример

Пусть отношение `Преподаватель` имеет атрибуты:

```text
ТабельныйНомер
ФИО
Кафедра
```

Тогда кортеж:

```text
(101, "Иванов Иван Иванович", "Информатика")
```

является одной записью отношения.

### Основные свойства реляционного отношения

В классической реляционной модели:

1. каждый атрибут имеет имя;
2. значения атрибута принадлежат одному домену;
3. каждый кортеж содержит одно значение каждого атрибута;
4. порядок строк не имеет смыслового значения;
5. порядок столбцов в математическом определении также не должен менять смысл отношения;
6. дубликаты кортежей в математическом отношении не рассматриваются как разные элементы множества.

В реальной СУБД таблица может иметь особенности, которых нет в строгом математическом определении отношения, поэтому **«реляционное отношение» и «таблица в интерфейсе СУБД» — связанные, но не абсолютно тождественные понятия**.

## 11. Что такое потенциальный ключ реляционного отношения?

**Потенциальный ключ** (candidate key) — это минимальный набор атрибутов, значения которого однозначно идентифицируют каждый кортеж отношения.

У потенциального ключа есть два главных свойства:

1. **уникальность** — два разных кортежа не должны иметь одинакового значения ключа;
2. **минимальность** — если убрать из ключа любой атрибут, он перестанет быть ключом.

### Пример

Есть отношение `Студент`:

| НомерЗачетки | ФИО | Телефон |
|---:|---|---|
| 241001 | Иванов И.И. | 89000000001 |
| 241002 | Петров П.П. | 89000000002 |

Если каждый номер зачётки уникален, то:

```text
{НомерЗачетки}
```

может быть потенциальным ключом.

В некоторых организациях уникальным может быть также личный код студента. Тогда в отношении существуют **несколько потенциальных ключей**.

### Первичный ключ

Из всех потенциальных ключей разработчик выбирает один как **первичный ключ (Primary Key)**.

Следовательно:

```text
Потенциальные ключи
        ↓
один выбран как
        ↓
Первичный ключ
```

## 12. Что такое внешний ключ реляционного отношения?

**Внешний ключ (Foreign Key)** — это атрибут или набор атрибутов дочернего отношения, значения которого ссылаются на значения первичного ключа (или другого подходящего уникального ключа) родительского отношения.

Главная задача внешнего ключа — **связать записи двух таблиц и обеспечить ссылочную целостность**.

### Пример

Есть таблица `Группы`:

| ID_Группы | Название |
|---:|---|
| 1 | ИВТ-21 |
| 2 | ИВТ-22 |

Есть таблица `Студенты`:

| ID_Студента | ФИО | ID_Группы |
|---:|---|---:|
| 101 | Иванов И.И. | 1 |
| 102 | Петров П.П. | 1 |
| 103 | Сидорова А.А. | 2 |

Здесь:

- `Группы.ID_Группы` — первичный ключ родительской таблицы;
- `Студенты.ID_Группы` — внешний ключ дочерней таблицы.

Значение `1` во внешнем ключе означает: студент относится к группе с `ID_Группы = 1`.

### Что важно

Внешний ключ **не обязан называться так же**, как первичный ключ, но обычно совпадение названий делает структуру понятнее.

Для внешнего ключа важно, чтобы типы и допустимые значения были совместимы с ключом, на который он ссылается.

LibreOffice Base отображает связи между первичным и внешним ключами в окне проектирования связей. citeturn574527search5

## 13. Какой тип связи реализует механизм внешних ключей?

Механизм внешних ключей непосредственно реализует **связь «один-ко-многим» (1:N)** между родительской и дочерней таблицами.

### Пример

Одна группа может содержать много студентов:

```text
Группа 1 ───────< Студент
```

То есть:

- одна запись в родительской таблице `Группы`;
- много записей в дочерней таблице `Студенты`.

Именно такая структура естественно выражается внешним ключом:

```text
Группы
ID_Группы (PK)
    ↑
    │
    └──────── ID_Группы (FK)
               Студенты
```

### Важное уточнение

Связь **1:1** тоже можно реализовать с помощью внешнего ключа, если на дочернем внешнем ключе дополнительно обеспечена уникальность.

Связь **M:N (многие-ко-многим)** обычно не реализуется одним внешним ключом. Для неё создают промежуточную таблицу.

Например:

```text
Студенты M ───< Студент_Дисциплина >─── M Дисциплины
```

Промежуточная таблица будет содержать внешние ключи на обе стороны.

## 14. Сравните структуры данных «Реляционное отношение» и «Таблица»

Эти понятия очень близки, но относятся к разным уровням описания.

| Реляционное отношение | Таблица в СУБД |
|---|---|
| Математическое понятие | Практическая структура хранения данных |
| Состоит из кортежей | Состоит из записей/строк |
| Содержит атрибуты | Содержит поля/столбцы |
| Для атрибутов задаются домены | Для полей задаются типы данных и ограничения |
| В классическом определении дубликаты кортежей не допускаются | В отдельных СУБД таблица может допускать дубликаты строк, если нет ограничений |
| Порядок кортежей не имеет значения | Порядок записей также не следует использовать как смысловой признак |
| Математическая модель | Реализация/представление этой модели |

### Вывод

Можно сказать:

> **Реляционное отношение — теоретическая основа, а таблица — привычная практическая форма реализации этого отношения в СУБД.**

Именно поэтому в большинстве учебных задач эти слова часто используются почти как синонимы, хотя строго математически это не совсем одно и то же.

## 15. Почему в интерфейсе реляционных СУБД используется термин «Таблица»?

Термин **«таблица»** используется потому, что реляционные отношения очень удобно представлять в виде двумерной структуры:

- **столбцы** соответствуют атрибутам;
- **строки** соответствуют кортежам;
- **ячейки** содержат значения.

Для пользователя такая форма интуитивно понятна.

### Почему это особенно удобно

Пользователь видит примерно следующее:

| Номер | ФИО | Группа |
|---:|---|---|
| 101 | Иванов И.И. | ИВТ-21 |
| 102 | Петров П.П. | ИВТ-21 |

Необязательно знать математическую теорию отношений, чтобы понять такую структуру.

Поэтому интерфейс СУБД обычно использует знакомый термин **«таблица»**, а в теории реляционных БД используется термин **«отношение»**.

LibreOffice Base также представляет хранимые данные в виде таблиц, а запись данных отображает как строку, а поля — как столбцы. citeturn574527search3

## 16. Как добавить таблицу в схему данных?

В контексте LibreOffice Base под **схемой данных** удобно понимать графическое представление таблиц и связей между ними в окне **Связи (Relationships)**.

### Пошагово в LibreOffice Base

#### Шаг 1. Открыть базу данных

3. В левой части окна выбрать раздел **Таблицы (Tables)**.

#### Шаг 2. Убедиться, что таблицы существуют

В разделе **Таблицы** должна отображаться нужная таблица. Если таблицы ещё нет, её сначала создают в режиме конструктора или с помощью мастера.

Для создания таблицы в режиме конструктора в LibreOffice Base выбирают:

**Таблицы → Создать таблицу в режиме конструктора**.

Официальная справка LibreOffice описывает именно такой путь создания таблицы. citeturn574527search3turn574527search0

#### Шаг 3. Открыть окно связей

В окне базы данных выбрать:

**Сервис/Инструменты → Связи (Tools → Relationships)**.

## 17. В чем отличие между таблицей в режиме конструктора и таблицей в режиме заполнения?

В LibreOffice Base таблица может использоваться в двух принципиально разных режимах.

### 1. Режим конструктора (Design View)

Этот режим предназначен для **описания структуры таблицы**.

В нём задают:

- имя поля;
- тип поля;
- описание поля;
- свойства поля;
- обязательность заполнения;
- значение по умолчанию;
- первичный ключ и другие параметры.

Например:

| Имя поля | Тип поля |
|---|---|
| ID_Студента | INTEGER |
| ФИО | VARCHAR |
| НомерЗачетки | VARCHAR |
| ID_Группы | INTEGER |

То есть конструктор отвечает прежде всего на вопрос:

> **«Как устроена таблица?»**

### 2. Режим заполнения/ввода данных

Здесь пользователь работает уже с **конкретными записями**.

Например:

| ID_Студента | ФИО | НомерЗачетки | ID_Группы |
|---:|---|---|---:|
| 101 | Иванов И.И. | 241001 | 1 |
| 102 | Петров П.П. | 241002 | 1 |

Этот режим отвечает на вопрос:

> **«Какие данные сейчас находятся в таблице?»**

### Главное различие

```text
Конструктор → структура
Заполнение  → данные
```

В официальной документации LibreOffice режим Design View предназначен для создания полей и определения их типов и свойств. citeturn574527search0

## 18. Как сделать поле таблицы ключевым?

В реляционной БД ключевым обычно делают поле, которое **однозначно идентифицирует запись**.

В LibreOffice Base это делается в **режиме конструктора таблицы**.

### Пошагово

1. Открыть базу данных.
2. Выбрать раздел **Таблицы**.
3. Найти нужную таблицу.
4. Нажать по ней правой кнопкой мыши.
5. Выбрать **Изменить / Edit** или открыть таблицу в режиме конструктора.
6. Выбрать поле, которое должно быть первичным ключом.
7. Щёлкнуть по строке поля правой кнопкой мыши.
8. Выбрать **Первичный ключ (Primary Key)**.
9. У выбранного поля появится значок ключа.
10. Сохранить изменения структуры таблицы.

Официальная документация LibreOffice прямо указывает, что в режиме конструктора поле можно назначить первичным ключом через контекстное меню **Primary Key**. Первичный ключ должен иметь уникальное значение для каждой записи. citeturn574527search0

### Пример

Таблица `Студенты`:

| Поле | Тип | Ключ |
|---|---|---|
| ID_Студента | INTEGER | 🔑 Первичный ключ |
| ФИО | VARCHAR | — |
| НомерЗачетки | VARCHAR | — |

Если `ID_Студента` уникален, он подходит для роли первичного ключа.

### Автоматическое заполнение ключа

Если используется числовой идентификатор, часто удобно установить для поля свойство **AutoValue / Автозначение = Yes / Да**. Тогда СУБД сможет автоматически формировать последовательные значения идентификатора, если это поддерживается используемым движком. citeturn574527search0

## 19. Что произойдет, если ни одно поле таблицы пользователь не сделал ключевым?

Если первичный ключ не назначен, таблица **не имеет формально определённого первичного ключа**.

Это приводит к нескольким проблемам:

1. Нельзя однозначно указать, какое поле идентифицирует запись.
2. На таблицу сложнее ссылаться из других таблиц через внешние ключи.
3. Некоторые операции редактирования могут быть ограничены.
4. В LibreOffice Base для некоторых типов БД первичный ключ необходим для нормального редактирования содержимого таблицы.

Официальная документация LibreOffice Base прямо отмечает, что Base использует первичный ключ для редактирования содержимого таблицы, а для некоторых систем БД он обязателен. citeturn574527search0

### Что может произойти на практике в LibreOffice

Если создать таблицу и не назначить ключ, данные иногда всё равно удаётся просматривать, но при попытке изменения записей Base или подключённая СУБД может сообщить, что невозможно однозначно определить изменяемую строку.

Поэтому в учебной и практической БД рекомендуется:

> **Для каждой основной таблицы заранее определить подходящий первичный ключ.**

## 20. Опишите, как установить и изменить связи между таблицами

Связь между таблицами устанавливается на основе **первичного ключа родительской таблицы** и соответствующего **внешнего ключа дочерней таблицы**.

### Пример структуры

Есть таблицы:

**Группы**

```text
ID_Группы (PK)
Название
```

**Студенты**

```text
ID_Студента (PK)
ФИО
ID_Группы (FK)
```

Нужно связать:

```text
Группы.ID_Группы
        ↓
Студенты.ID_Группы
```

### Пошагово в LibreOffice Base

#### Шаг 1. Создать таблицы

Обе таблицы должны уже существовать.

#### Шаг 2. Создать первичный ключ родителя

В таблице `Группы` поле `ID_Группы` делаем первичным ключом.

#### Шаг 3. Создать внешний ключ в дочерней таблице

В таблице `Студенты` должно быть поле `ID_Группы`, тип которого совместим с ключом родительской таблицы.

#### Шаг 4. Открыть окно связей

Выбрать:

**Сервис/Инструменты → Связи (Tools → Relationships)**.

#### Шаг 5. Добавить таблицы

Через **Добавить таблицы (Add Tables)** добавить `Группы` и `Студенты`.

#### Шаг 6. Соединить поля

Можно просто перетащить поле первичного ключа на соответствующее поле внешнего ключа.

Например:

```text
Группы.ID_Группы  ─────────────→  Студенты.ID_Группы
```

LibreOffice создаст линию между таблицами.

Официальная документация Base прямо описывает создание связи через перетаскивание поля одной таблицы на соответствующее поле другой. citeturn574527search5

#### Шаг 7. Настроить свойства связи

Если дважды щёлкнуть по линии связи, откроется окно **Relations / Связи**, где можно определить поля связи и, если поддерживает используемая БД, параметры обновления и удаления. citeturn183987search0turn183987search9

### Как изменить связь

1. Открыть **Инструменты → Связи**.
2. Найти нужную линию.
3. Дважды щёлкнуть по линии.
4. Изменить параметры в окне связи.
5. Сохранить изменения.

### Как удалить связь

1. Выбрать линию связи.
2. Нажать **Delete** или использовать соответствующую команду контекстного меню.

Официальная справка LibreOffice также указывает, что существующую связь можно удалить, выделив соединяющую линию и нажав Delete. citeturn574527search5

## 21. Что такое ссылочная целостность?

**Ссылочная целостность** — это правило, согласно которому значения внешнего ключа должны оставаться корректными по отношению к ключу родительской таблицы.

Проще говоря:

> **Нельзя допустить, чтобы дочерняя запись ссылалась на несуществующую родительскую запись.**

### Пример

Есть таблица `Группы`:

| ID_Группы | Название |
|---:|---|
| 1 | ИВТ-21 |
| 2 | ИВТ-22 |

В `Студенты` есть внешний ключ `ID_Группы`.

Тогда допустимо:

```text
Студент → ID_Группы = 1
```

потому что группа `1` существует.

А такое значение:

```text
Студент → ID_Группы = 99
```

недопустимо, если группы `99` нет.

### Зачем нужна ссылочная целостность

Она предотвращает появление так называемых **висячих ссылок** или записей-сирот.

Например, если группа удалена, но её студенты продолжают ссылаться на несуществующий `ID_Группы`, БД становится противоречивой.

Поэтому СУБД контролирует операции INSERT и UPDATE во внешнем ключе, а также правила удаления и изменения родительских ключей.

## 22. Что такое каскадное обновление и каскадное удаление? Приведите пример

**Каскадное обновление** и **каскадное удаление** — это правила, которые определяют, что произойдёт с дочерними записями, если изменяется или удаляется связанная запись родительской таблицы.

### Каскадное обновление

**Каскадное обновление (ON UPDATE CASCADE)** означает:

> Если значение первичного ключа родительской записи изменилось, соответствующие значения внешнего ключа в дочерней таблице изменяются автоматически.

### Пример

Было:

**Группы**

```text
ID_Группы = 1
Название = ИВТ-21
```

**Студенты**

```text
ID_Студента = 101
ID_Группы = 1
```

Если идентификатор группы изменяется с `1` на `10`, при каскадном обновлении автоматически получится:

```text
Группы.ID_Группы      = 10
Студенты.ID_Группы    = 10
```

Связь не нарушается.

### Каскадное удаление

**Каскадное удаление (ON DELETE CASCADE)** означает:

> При удалении родительской записи автоматически удаляются связанные с ней дочерние записи.

### Пример

Было:

**Группы**

```text
ID_Группы = 1
```

**Студенты**

```text
101 → группа 1
102 → группа 1
103 → группа 2
```

Если удалить группу `1` и включено каскадное удаление, автоматически будут удалены студенты `101` и `102`.

Студент `103` останется.

### Почему с каскадным удалением нужно быть осторожным

Удаление одной родительской записи может вызвать удаление большого числа дочерних записей. LibreOffice отдельно предупреждает об этом: при каскадном удалении удаляются все связанные записи во внешних таблицах. 

### Где включить эти параметры в LibreOffice

1. Открыть **Инструменты → Связи**.
2. Дважды щёлкнуть по линии между таблицами.
3. Открывается окно свойств связи.
4. В разделах **Update options / Параметры обновления** и **Delete options / Параметры удаления** выбрать нужное поведение.
5. Для обновления выбрать **Cascade Update / Каскадное обновление**.
6. Для удаления выбрать **Cascade Delete / Каскадное удаление**, если оно действительно необходимо.

Набор доступных параметров зависит от используемой СУБД. В документации LibreOffice среди вариантов указаны «Нет действия», «Каскадное обновление», «Установить NULL», а для удаления — в том числе «Каскадное удаление». citeturn183987search9

## 23. Можно ли добавлять/удалять произвольные данные в родительскую таблицу? В дочернюю?

Здесь важно разделить **добавление** и **удаление**.

### 1. Родительская таблица

#### Добавление

Обычно **новую родительскую запись можно добавить**, если она удовлетворяет ограничениям таблицы:

- значение первичного ключа уникально;
- обязательные поля заполнены;
- значения соответствуют своим доменам;
- выполнены другие ограничения.

Например, можно добавить новую группу:

```text
ID_Группы = 3
Название = ИВТ-23
```

Она пока может вообще не иметь студентов. Это допустимо.

#### Удаление

Удалять родительскую запись **произвольно нельзя**, если на неё уже ссылаются записи дочерней таблицы и выбран режим, запрещающий такое удаление.

Например, если группа `1` имеет студентов, СУБД может запретить удаление группы, чтобы не нарушить ссылочную целостность.

Возможны другие правила:

- **запретить удаление**;
- **каскадно удалить** дочерние записи;
- **установить NULL** во внешнем ключе, если это разрешено;
- использовать другое поддерживаемое СУБД действие.

### 2. Дочерняя таблица

#### Добавление

Произвольное добавление возможно **только при соблюдении внешнего ключа**.

Например, если в `Группы` существуют только:

```text
1 — ИВТ-21
2 — ИВТ-22
```

то в таблицу `Студенты` можно добавить:

```text
ID_Группы = 1
```

или:

```text
ID_Группы = 2
```

Но нельзя указать:

```text
ID_Группы = 999
```

если такой группы не существует.

#### Удаление

Удалить запись из дочерней таблицы обычно проще: удаление студента, например, не нарушает существование группы.

То есть можно удалить:

```text
Студент 101 → группа 1
```

и группа `1` после этого продолжит существовать.

### Итоговая таблица

| Операция | Родительская таблица | Дочерняя таблица |
|---|---|---|
| Добавление | Обычно да, если соблюдены ограничения | Да, но внешний ключ должен ссылаться на существующего родителя |
| Удаление | Может быть запрещено из-за существующих ссылок | Обычно возможно, если на запись не ссылается другая таблица |
| Изменение ключа | Может затрагивать дочерние записи | Должно сохранять корректность внешнего ключа |

### Главное правило

> **Родительская запись может существовать без дочерних, но дочерняя запись с внешним ключом не может ссылаться на несуществующего родителя.**

Именно это правило лежит в основе ссылочной целостности.

# Практическая часть в LibreOffice Base

Ниже приведён вариант последовательности действий, который пригодится при выполнении лабораторной работы непосредственно в LibreOffice Base.

## 1. Создание новой базы

1. Открыть LibreOffice.
2. Выбрать **Файл → Создать → База данных**.
3. Откроется мастер базы данных.
4. Создать новую базу и завершить мастер.
5. Сохранить файл, например `Лабораторная_1.odb`.

LibreOffice указывает, что для создания новой базы используется команда **File → New → Database**. citeturn183987search1

---

## 2. Создание первой таблицы

Например, создадим таблицу `Группы`.

1. Слева выбрать **Таблицы**.
2. Выбрать **Создать таблицу в режиме конструктора**.
3. Ввести поля:

| Имя поля | Тип |
|---|---|
| ID_Группы | INTEGER |
| Название | VARCHAR |
| Курс | INTEGER |

4. Для `ID_Группы` установить **Первичный ключ**.
5. При необходимости включить **Автозначение = Да**.
6. Сохранить таблицу под именем `Группы`.

В режиме конструктора LibreOffice позволяет создавать поля, выбирать их тип и задавать свойства. citeturn574527search0

## 3. Создание дочерней таблицы

Создадим `Студенты`:

| Имя поля | Тип |
|---|---|
| ID_Студента | INTEGER |
| НомерЗачетки | VARCHAR |
| ФИО | VARCHAR |
| ID_Группы | INTEGER |

Для `ID_Студента` задаём первичный ключ.

Поле `ID_Группы` пока является обычным полем, но впоследствии оно будет участвовать во внешнем ключе.

|---:|---|---|---:|

## 5. Создание связи

1. Открыть **Инструменты → Связи**.
2. Нажать **Добавить таблицы**.
3. Добавить `Группы` и `Студенты`.
4. Найти поле `ID_Группы` в таблице `Группы`.
5. Перетащить его на `ID_Группы` в таблице `Студенты`.
6. Между таблицами появится линия.

Получится:

```text
             Группы
       ┌─────────────────┐
       │ ID_Группы  🔑   │
       │ Название        │
       │ Курс            │
       └────────┬────────┘
                │ 1
                │
                │ N
       ┌────────▼────────┐
       │ Студенты        │
       │ ID_Студента 🔑  │
       │ НомерЗачетки    │
       │ ФИО             │
       │ ID_Группы       │
       └─────────────────┘
```

Таким образом, на схеме будет отображаться связь **1:N**.

LibreOffice Base официально поддерживает создание связи перетаскиванием поля одной таблицы на поле другой и настройку свойств через двойной щелчок по линии связи. citeturn574527search5turn183987search0

## 6. Проверка ссылочной целостности

После создания связи можно проверить её работу.

### Проверка 1. Корректная вставка

Попробовать добавить студенту:

```text
ID_Группы = 2
```

Такой ввод должен быть допустим, потому что группа `2` существует.

### Проверка 2. Некорректная вставка

Попробовать ввести:

```text
ID_Группы = 999
```

Если ограничение внешнего ключа действительно создано и поддерживается используемым движком, СУБД должна отклонить такую запись, потому что родительской группы `999` нет.

### Проверка 3. Удаление родителя

Попробовать удалить группу `1`, если в ней находятся студенты.

Результат зависит от настроек связи:

- при **запрете удаления** операция будет отклонена;
- при **каскадном удалении** будут удалены и связанные студенты;
- при другом режиме срабатывает соответствующее правило.

# Краткая шпаргалка по терминам

| Термин | Смысл |
|---|---|
| **ИС** | Система для сбора, хранения, обработки и предоставления информации |
| **БД** | Организованная совокупность данных |
| **СУБД** | Программное средство управления БД |
| **Домен** | Множество допустимых значений и ограничений для атрибута |
| **Атрибут** | Именованное свойство отношения; в таблице соответствует полю/столбцу |
| **Отношение** | Математическая структура реляционной модели данных |
| **Таблица** | Практическое табличное представление отношения в СУБД |
| **Кортеж** | Одна запись отношения; аналог строки таблицы |
| **Первичный ключ (PK)** | Выбранный ключ, однозначно идентифицирующий запись |
| **Потенциальный ключ** | Любой минимальный уникальный набор атрибутов, подходящий для идентификации |
| **Внешний ключ (FK)** | Поле, ссылающееся на ключ родительской таблицы |
| **Ссылочная целостность** | Запрет некорректных ссылок из дочерних записей на отсутствующих родителей |
| **Каскадное обновление** | Автоматическое изменение внешних ключей при изменении родительского ключа |
| **Каскадное удаление** | Автоматическое удаление связанных дочерних записей при удалении родителя |
| **Схема данных** | Набор таблиц и связей между ними |

# Факты (полезности)

1. **БД — фундамент информационной системы.**
2. **СУБД — программа для управления базой данных.**
3. **Домен задаёт допустимые значения.**
4. **Атрибут — именованное поле отношения.**
5. **Реляционное отношение в СУБД обычно представляется таблицей.**
6. **Кортеж — строка (запись), атрибут — столбец (поле).**
7. **Первичный ключ уникально идентифицирует запись.**
8. **Внешний ключ связывает дочернюю таблицу с родительской.**
9. **Обычная схема «родитель → дети» реализует связь 1:N.**
10. **Ссылочная целостность не позволяет дочерней записи ссылаться на несуществующего родителя.**
11. **Каскадное обновление переносит изменение ключа на дочерние записи.**
12. **Каскадное удаление может удалить вместе с родителем все связанные дочерние записи.**
13. **В LibreOffice Base таблицу создают через раздел «Таблицы», а связи между таблицами — через «Инструменты → Связи».**
