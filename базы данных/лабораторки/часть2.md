## 1. Почему формы являются элементом информационной системы ИС БД?

Информационная система (ИС) — это не просто набор таблиц, а средство, с которым работают **пользователи**. Таблицы хранят данные, запросы их выбирают, отчёты выводят, а **формы** — это интерфейс, через который человек вводит, просматривает и редактирует данные.

Причины, по которым формы — неотъемлемая часть ИС:

- **Удобство и наглядность.** Пользователь (секретарь деканата) не обязан знать структуру БД и открывать таблицы напрямую. Он видит понятную экранную форму с подписями полей.
- **Защита данных.** Через форму можно ограничить действия: запретить удаление, скрыть служебные поля (например, ID), разрешить только просмотр.
- **Контроль ввода.** Вместо ввода кода кафедры вручную в форме ставится список с названиями кафедр — меньше ошибок.
- **Работа со связанными данными.** В одной форме можно показать данные нескольких таблиц (кафедра и её преподаватели).
- **Разделение ролей.** Разработчик работает с таблицами и запросами, а конечный пользователь — только с формами.

**Вывод:** формы замыкают цепочку «данные → обработка → интерфейс пользователя» и превращают набор таблиц в полноценную информационную систему.

## 2. Что такое режим дизайна при создании форм?

**Режим дизайна (Design View / «Режим разработки»)** — это режим, в котором форма **создаётся и редактируется вручную**, как макет: можно добавлять, перемещать, менять размеры и свойства элементов управления (поля, подписи, кнопки, списки).

Ключевые особенности:

- Форма на экране — это «чертёж», данные в ней не вводятся.
- Доступны панели инструментов **«Элементы управления формы»** и **«Конструктор форм»**.
- Двойной клик (или ПКМ → *Элемент управления…*) открывает **свойства** элемента: источник данных, подпись, формат, обязательность и т. д.
- Обратный режим — **режим ввода данных** (рабочий режим формы), где пользователь работает с данными.

**Как переключаться:** в окне формы кнопка **«Режим разработки»** на панели «Конструктор форм» (или меню *Вид → Панели инструментов → Конструктор форм*). Включена — режим дизайна, выключена — режим работы.

Как создать форму в режиме дизайна: *Формы → Создать форму в режиме разработки…* Откроется пустой Writer-документ, на который вручную добавляются элементы.

## 3. Что такое мастер для создания форм?

**Мастер форм** — это пошаговый помощник, который автоматически создаёт форму на основе выбранной таблицы или запроса. Пользователь отвечает на вопросы (какие поля, какое расположение, какой стиль), а мастер сам размещает элементы управления и связывает их с данными.

Запуск: **Формы → Использовать мастер для создания формы…**

Плюсы: быстро, без ручной вёрстки, подходит для типовых форм.
Минус: ограниченная гибкость — потом форму обычно дорабатывают в режиме дизайна.

## 4. Сколько шагов составляет полный цикл мастера форм?

Полный цикл мастера форм в LibreOffice Base — **8 шагов**:

| № | Шаг | Что делаем |
|---|-----|-----------|
| 1 | **Выбор полей** | Выбираем таблицу/запрос и переносим нужные поля в форму (`>`, `>>`) |
| 2 | **Установка субформы** | Решаем, нужна ли субформа (флажок «Добавить субформу») |
| 3 | **Добавление полей субформы** | Выбираем таблицу и поля для субформы |
| 4 | **Получение объединённых полей** | Указываем поля связи между главной формой и субформой |
| 5 | **Расположение элементов управления** | Выбираем макет: столбцы с подписями слева/сверху, таблица, блок |
| 6 | **Установка режима ввода данных** | Только ввод новых данных / запрет изменения, удаления, добавления |
| 7 | **Применение стилей** | Выбираем цвет фона, рамку полей |
| 8 | **Задание имени формы** | Вводим имя и выбираем: *работать с формой* или *изменить форму* |

> Если субформа не нужна, шаги 3 и 4 пропускаются — получается **сокращённый цикл (6 шагов)**.

## 5. Когда мастер форм использует сокращённый, а не полный цикл?

Мастер использует **сокращённый цикл**, когда **субформа не создаётся**, то есть на шаге 2 флажок **«Добавить субформу» не установлен**.

Тогда пропускаются:
- шаг «Добавление полей субформы»;
- шаг «Получение объединённых полей».

Остаются шаги: выбор полей → расположение элементов → режим ввода данных → стили → имя формы.

**Пример:** форма просто для таблицы `Кафедра` (поля Наименование, Аудитория) — субформа не нужна, цикл сокращённый. Форма «Кафедра и её преподаватели» — нужна субформа, цикл полный.

## 6. Почему для каждой таблицы рекомендуется создавать минимум 2 формы?

Потому что у одних и тех же данных есть **две разные задачи**:

1. **«Линейная» (столбцовая) форма** — для **ввода и редактирования одной записи**: удобно заполнять, видны все поля крупно и с подписями.
2. **«Табличная» форма** — для **просмотра и сравнения многих записей сразу**: видно сразу много строк, удобно искать и сортировать.

Дополнительные причины:

- Разные формы можно дать **разным пользователям** (одним — просмотр, другим — ввод).
- Табличная форма хороша для обзора, но неудобна при большом числе полей (не помещаются по ширине); линейная — наоборот.
- Это принцип **удобства использования (usability)**: интерфейс должен соответствовать задаче.

**Пример для таблицы `Студент`:**
- форма «Студент_ввод» (линейная) — карточка студента: ФИО, номер зачётки, дата рождения, пол;
- форма «Студент_список» (табличная) — таблица всех студентов на экране.

## 7. Что такое «линейная» форма?

**Линейная (столбцовая, «карточная») форма** — форма, в которой **на экране отображается одна запись**, а поля расположены **друг под другом** (в столбец), каждое с подписью.

Особенности:
- Одна запись на экран, переключение между записями — **навигатором** внизу (◄ ► |◄ ►|).
- Удобна для ввода и подробного просмотра данных.
- В мастере форм выбирается на шаге «Расположение элементов управления» (первый вариант — **«Столбцы — подписи слева»** или **«Столбцы — подписи сверху»**).

**Пример (`Преподаватель`):**
```
Таб_номер:   [ 1001          ]
ФИО:         [ Иванов И.И.   ]
Кафедра:     [ Алгебры       ]
Должность:   [ Доцент        ]
```

---

## 8. Что такое «табличная» форма?

**Табличная форма** — форма, в которой **записи отображаются в виде таблицы**: каждая запись — строка, каждое поле — столбец. На экране видно сразу множество записей.

Особенности:
- Похожа на открытую таблицу, но с возможностью настроить внешний вид, ограничить права, добавить списки.
- Удобна для просмотра, сортировки, фильтрации данных.
- В мастере выбирается вариант расположения **«Таблица»** (последний/пятый значок на шаге «Расположение элементов управления»).

**Пример (`Студент`):**

| Номер_зачетки | ФИО | Специальность | Пол |
|---|---|---|---|
| 100001 | Петров П.П. | 010101 | М |
| 100002 | Сидорова А.В. | 010101 | Ж |

## 9. Как в форме запретить изменения и удаления существующих данных и добавление новых данных?

Есть два способа.

### Способ 1. В мастере форм (шаг 6 — «Установка режима ввода данных»)

1. Выбрать вариант **«Эта форма будет отображать все данные»**.
2. Установить флажки:
   - ☑ **Не разрешать изменение существующих данных**
   - ☑ **Не разрешать удаление существующих данных**
   - ☑ **Не разрешать добавление новых данных**
3. Нажать «Далее».

(Вариант **«Форма предназначена только для ввода новых данных»** — наоборот, показывает пустую форму, существующие записи не видны.)

### Способ 2. В свойствах готовой формы

1. Открыть форму в **режиме разработки**.
2. ПКМ по свободному месту формы (или на панели «Навигатор форм») → **Форма…** (*Properties*).
3. Вкладка **«Данные»**, установить:
   - **Разрешить изменения** → *Нет*
   - **Разрешить удаления** → *Нет*
   - **Разрешить добавления** → *Нет*
4. Сохранить форму.

Результат: форма работает **только на просмотр**.

## 10. Какие панели инструментов используют мастер форм в режиме дизайна?

При редактировании формы (после мастера) в режиме разработки используются:

1. **Элементы управления формы** (*Form Controls*) — добавление объектов: поле, подпись, список, кнопка, флажок и т. д.
2. **Конструктор форм** (*Form Design*) — переключение режима разработки, свойства элемента/формы, мастера элементов, навигатор форм, порядок активации.
3. **Навигация по форме** (*Form Navigation*) — навигатор записей: переход, добавление, удаление, сортировка, фильтр (в рабочем режиме).
4. **Стандартная панель** и **панель форматирования** Writer — для оформления текста, шрифтов, выравнивания.

Включаются через **Вид → Панели инструментов**.

## 12. Как отредактировать форму?

1. В главном окне Base слева выбрать **«Формы»**.
2. В списке форм нажать **ПКМ по нужной форме → Правка** (*Edit*).
3. Форма откроется в **режиме разработки**.
4. Внести изменения:
   - **переместить** элемент — перетащить мышью;
   - **изменить размер** — потянуть за маркеры по краям;
   - **изменить подпись/свойства** — двойной клик по элементу (или ПКМ → *Элемент управления…*);
   - **удалить** — выделить и нажать `Delete`;
   - **добавить** — выбрать объект на панели «Элементы управления формы» и «нарисовать» его на форме.
5. Сохранить: **Ctrl+S**.
6. Выключить кнопку **«Режим разработки»**, чтобы проверить работу формы.
7. Закрыть форму (сохранив изменения).

**Пример:** в форме `Студент` переименовать подпись «Номер_зачетки» в «№ зачётной книжки» — двойной клик по надписи → поле **«Заголовок»** → ввести новый текст.

## 13. Как на рабочий стол формы добавить объект «список»?

Пример: в форме `Преподаватель` заменить поле «Кафедра» (число-код) на **список с названиями кафедр**.

1. Открыть форму через **ПКМ → Правка** (режим разработки).
2. Если на форме уже есть текстовое поле «Кафедра» — **удалить** его (и его подпись, или оставить подпись).
3. На панели **«Элементы управления формы»** включить **«Мастер элементов»** (значок волшебной палочки).
4. Выбрать объект **«Список»** (List box) и мышью **нарисовать** прямоугольник на форме.
5. Откроется **Мастер списков** (см. следующий вопрос) — выполнить его шаги.
6. Добавить **подпись** («Кафедра»), если её нет.
7. Сохранить форму, выключить режим разработки и проверить.

## 14. Как установить связь между объектом типа «список» и исходной таблицей?

Связь настраивается в **Мастере списков** (4 шага) либо вручную в свойствах.

### Через мастер

1. **Шаг 1. Выбор таблицы** — выбираем **справочную таблицу**, откуда берутся значения списка (например, `Кафедра`).
2. **Шаг 2. Выбор отображаемого поля** — выбираем поле, которое видит пользователь (например, `Наименование`).
3. **Шаг 3. Связь полей** (ключевой шаг):
   - **«Поле в таблице значений»** — поле справочника, которое является ключом (`ID` из таблицы `Кафедра`);
   - **«Поле в таблице списка»** — поле в **таблице формы**, куда записывается значение (`Кафедра` в таблице `Преподаватель`).
4. **Шаг 4. Готово** — задаём подпись (необязательно) и завершаем.

### Что получается

Пользователь **видит** «Алгебры и геометрии», а в таблицу `Преподаватель` **записывается** код кафедры (`ID`). Так обеспечивается ссылочная целостность — нельзя ввести несуществующую кафедру.

### Вручную (свойства списка → вкладка «Данные»)

- **Тип содержимого списка:** *SQL*;
- **Содержимое списка:** `SELECT "Наименование", "ID" FROM "Кафедра"`;
- **Связанное поле:** `Кафедра` (в таблице формы).

## 15. Для чего используются субформы?

**Субформа** — это форма, вложенная в основную (главную), которая показывает **связанные записи из другой таблицы** (связь «один-ко-многим»).

Назначение:

- Отображать данные **двух таблиц одновременно**: в главной форме — запись «один», в субформе — все связанные записи «многие».
- При переходе по записям главной формы **содержимое субформы автоматически меняется**.
- Наглядно показывать иерархию данных без ручных запросов.

**Примеры на «Деканате»:**

| Главная форма | Субформа | Связь |
|---|---|---|
| `Кафедра` | `Преподаватель` (все преподаватели кафедры) | `Кафедра.ID = Преподаватель.Кафедра` |
| `Студент` | `Успеваемость` (все оценки студента) | `Студент.Номер_зачетки = Успеваемость.Номер_зачетки` |
| `Специальность` | `Студент` (студенты специальности) | `Специальность.Код = Студент.Специальность` |

**Как создать:** в мастере форм на шаге 2 установить флажок **«Добавить субформу»** → шаг 3: выбрать таблицу и поля субформы → шаг 4: указать **поля связи**.

## 16. Почему в формах на основе субформ не рекомендуется ввод и редактирование данных?

Формы с субформами лучше использовать **для просмотра**, а не для ввода, потому что:

1. **Нарушение целостности.** Две таблицы редактируются одновременно: при добавлении записи в субформу связанный ключ может быть не заполнен или заполнен неверно.
2. **Риск потери данных.** Сохранение главной и подчинённой записи происходит **раздельно**: можно создать «осиротевшую» запись в субформе или удалить запись главной формы, у которой есть подчинённые.
3. **Путаница пользователя.** На экране два набора навигации и два независимых места сохранения — легко внести данные не в ту запись.
4. **Сложность проверок.** Ограничения (обязательность, типы, уникальность) двух таблиц действуют одновременно, ошибки сложнее понять.
5. **Неудобство ввода.** Субформа обычно табличная и небольшая, полей может не хватать для ввода.

**Практическая рекомендация:**
- Для **ввода** — отдельные простые формы по каждой таблице (с списками для внешних ключей).
- Для **просмотра** связанных данных — форма с субформой, где в мастере (шаг 6) включено: *не разрешать изменение, удаление и добавление*.
