# Глава 1. Основные понятия баз данных

## 1. База данных (БД)

**Определение.** База данных (БД) — это организованная совокупность структурированных данных, хранимых в памяти вычислительной системы и отражающих состояние объектов некоторой предметной области, а также связи между ними. БД предназначена для длительного хранения данных и их использования множеством пользователей и приложений.

### Классификация БД

По **модели данных**:
- Иерархические
- Сетевые
- Реляционные
- Объектно-ориентированные
- Объектно-реляционные
- NoSQL (документные, ключ-значение, графовые, колоночные)

По **характеру хранимой информации**:
- Фактографические (краткие сведения об объектах в строго определённом формате)
- Документальные (документы произвольного формата — тексты, изображения, звук)

По **способу распределения данных**:
- Централизованные (хранятся на одном компьютере/сервере)
- Распределённые (данные разнесены по нескольким узлам сети)

По **степени доступа**:
- Локальные (однопользовательские)
- Многопользовательские (в т.ч. с архитектурой «клиент-сервер»)

**Примечание.** Не следует путать БД с СУБД: БД — это сами данные, а СУБД — программное средство для работы с ними (см. п. 4).

---

## 2. Информационная система (ИС)

**Определение.** Информационная система (ИС) — это совокупность взаимосвязанных технических, программных и организационных средств, а также персонала, предназначенная для сбора, хранения, обработки, поиска и выдачи информации, необходимой для решения задач управления и принятия решений в определённой предметной области.

### Классификация ИС

По **степени автоматизации**:
- Ручные
- Автоматизированные (человек + техника)
- Автоматические

По **характеру использования информации**:
- Информационно-справочные (поисковые)
- Информационно-решающие (управляющие, советующие)

По **сфере применения**:
- Экономические (бухгалтерские, финансовые)
- Медицинские
- Технологические (АСУ ТП)
- Обучающие
- Геоинформационные (ГИС) и др.

По **масштабу**:
- Настольные (для одного пользователя)
- Групповые (отдел)
- Корпоративные (предприятие)

**Важно.** ИС — понятие более широкое, чем БД: БД является лишь одним из компонентов (ядром хранения данных) информационной системы. ИС включает также интерфейсы, бизнес-логику, персонал и регламенты работы.

---

## 3. Информационная система по базе данных (ИСБД)

**Определение.** ИСБД — это информационная система, ядром которой является база данных, то есть система, в которой хранение, обработка и предоставление информации организованы через СУБД и структурированную БД (в отличие от ИС, использующих неструктурированные файлы или иные способы хранения).

### Особенности ИСБД
- Данные хранятся централизованно (или логически централизованно при распределённой БД) и структурированно.
- Доступ к данным осуществляется через СУБД, а не напрямую к файлам.
- Обеспечивается независимость прикладных программ от способа физического хранения данных.
- Поддерживается многопользовательский доступ с разграничением прав.

**Сравнение ИС и ИСБД:**

| Признак | ИС (общий случай) | ИСБД |
|---|---|---|
| Способ хранения данных | Может быть любым (файлы, БД и т.д.) | Обязательно структурированная БД |
| Наличие СУБД | Не обязательно | Обязательно |
| Целостность и непротиворечивость данных | Не гарантируется автоматически | Поддерживается средствами СУБД |
| Пример | Система учёта на разрозненных Excel-файлах | Система учёта на основе PostgreSQL/MySQL |

## 4. Система управления базой данных (СУБД)

**Определение.** СУБД — это комплекс программных и языковых средств, предназначенный для создания, ведения (наполнения, обновления) и совместного использования баз данных многими пользователями и приложениями, а также для обеспечения целостности, безопасности и эффективного доступа к данным.

### Основные функции СУБД
1. Управление данными во внешней памяти.
2. Управление буферами оперативной памяти.
3. Управление транзакциями (обеспечение свойств ACID: атомарность, согласованность, изолированность, долговечность).
4. Журнализация и восстановление БД после сбоев.
5. Поддержание языков БД (DDL — язык определения данных, DML — язык манипулирования данными, например SQL).
6. Обеспечение защиты и разграничения прав доступа.

### Классификация СУБД

По **модели данных**: иерархические, сетевые, реляционные, объектно-ориентированные (см. п. 5).

По **степени распределённости**:
- Локальные (все компоненты на одном компьютере)
- Распределённые (данные и/или компоненты СУБД размещены на разных узлах)

По **способу доступа к БД**:
- Файл-серверные (Access — устаревший подход)
- Клиент-серверные (MySQL, PostgreSQL, Oracle, MS SQL Server)
- Встраиваемые (SQLite)

**Примечание/сравнение.** БД — это данные; СУБД — это инструмент управления этими данными; ИС — это система, использующая БД (через СУБД) для решения прикладных задач пользователя. Соотношение можно представить так:

`ИС ⊃ ИСБД ⊃ (СУБД + БД)`

## 5. Три математические модели данных

Исторически выделяют три классические математические (логические) модели организации данных в БД: **иерархическую**, **сетевую** и **реляционную**.

### 5.1. Иерархическая модель

**Определение.** Данные организованы в виде дерева (иерархии): каждый элемент (узел) имеет ровно одного «родителя» (кроме корневого) и может иметь несколько «потомков».

**Особенности:**
- Отношения между записями — только «один ко многим» (1:М).
- Быстрый доступ при движении по дереву сверху вниз.
- Проблема представления связей «многие ко многим» (M:N) — требует дублирования данных или искусственных узлов.
- Пример реализации: IMS (IBM), файловые системы, XML-документы.

### 5.2. Сетевая модель

**Определение.** Обобщение иерархической модели: узел (запись) может иметь **несколько родителей**, то есть данные представлены в виде произвольного графа связей.

**Особенности:**
- Поддерживает связи M:N напрямую (без дублирования данных).
- Более гибкая, чем иерархическая, но и более сложная в проектировании и навигации.
- Доступ к данным — навигационный (через явные указатели/цепочки), что требует от прикладного программиста знания физической структуры БД.
- Стандартизирована организацией CODASYL.

### 5.3. Реляционная модель

**Определение.** Данные представлены в виде совокупности двумерных таблиц (отношений), связанных между собой по значениям ключевых полей. Имеет строгое математическое обоснование на основе теории множеств и реляционной алгебры (Э. Кодд, 1970).

**Особенности:**
- Данные и связи между ними представлены единообразно — таблицами.
- Доступ к данным декларативный (через язык запросов, например SQL), а не навигационный.
- Поддерживает все типы связей: 1:1, 1:М, М:N (последняя — через промежуточную таблицу).
- Опирается на понятия: отношение, кортеж, атрибут, домен, первичный и внешний ключ, нормальные формы.

### Сравнение трёх моделей

| Критерий | Иерархическая | Сетевая | Реляционная |
|---|---|---|---|
| Структура | Дерево | Граф | Множество таблиц |
| Типы связей | Только 1:М | 1:М и M:N | 1:1, 1:М, M:N |
| Способ доступа | Навигационный | Навигационный | Декларативный (SQL) |
| Гибкость проектирования | Низкая | Средняя | Высокая |
| Математическая основа | Теория графов (деревья) | Теория графов | Теория множеств, реляционная алгебра |
| Независимость от физической структуры | Низкая | Низкая | Высокая |
| Современное применение | Ограничено (XML, реестры) | Редко | Широко (большинство СУБД) |

**Примечание.** Иногда к «трём моделям» также относят вместо сетевой — объектно-ориентированную или многомерную модель, в зависимости от учебной программы; в классической (исторической) трактовке речь идёт именно об иерархической, сетевой и реляционной моделях как о трёх этапах эволюции логических моделей данных.

## 6. Реляционная модель данных (подробно)

**Определение.** Реляционная модель данных — это способ организации данных в виде набора отношений (таблиц), где каждое отношение представляет собой множество кортежей (строк), а порядок строк и столбцов не имеет значения для модели.

### Основные понятия

| Термин | Определение | Соответствие в таблице |
|---|---|---|
| Отношение (relation) | Математическое множество кортежей | Таблица |
| Кортеж (tuple) | Упорядоченный набор значений атрибутов | Строка (запись) |
| Атрибут (attribute) | Именованный столбец отношения | Столбец (поле) |
| Домен (domain) | Множество допустимых значений атрибута | Тип данных столбца |
| Степень отношения | Количество атрибутов | Количество столбцов |
| Мощность отношения | Количество кортежей | Количество строк |

### Ключи
- **Первичный ключ (Primary Key, PK)** — атрибут (или набор атрибутов), однозначно идентифицирующий каждый кортеж; не может содержать NULL и должен быть уникальным.
- **Внешний ключ (Foreign Key, FK)** — атрибут, ссылающийся на первичный ключ другого (или того же) отношения; обеспечивает ссылочную целостность (referential integrity).
- **Потенциальный (возможный) ключ** — любой минимальный набор атрибутов, способный уникально идентифицировать кортеж; из потенциальных ключей выбирается один первичный.

### Свойства отношений
1. Отсутствие дублирующихся кортежей (уникальность строк).
2. Отсутствие упорядоченности кортежей.
3. Отсутствие упорядоченности атрибутов.
4. Атомарность значений атрибутов (в классической, 1НФ-версии модели — каждое значение неделимо).

### Целостность данных
- **Целостность сущностей** — первичный ключ не может быть NULL.
- **Целостность по ссылкам** — значение внешнего ключа либо NULL, либо совпадает с существующим значением первичного ключа связанного отношения.

### Нормализация (кратко)
Процесс приведения отношений к нормальным формам (1НФ, 2НФ, 3НФ, НФБК и др.) с целью устранения избыточности данных и аномалий вставки/обновления/удаления.

**Итоговое сравнение:** в отличие от иерархической и сетевой моделей, где связи задаются физически (указателями), в реляционной модели связи задаются **логически**, через совпадение значений ключей, что и обеспечивает её независимость от физического хранения и гибкость при изменении структуры БД.
