# CommandParser.java — разбор и проверка команды

## Назначение класса

`CommandParser` получает строку и проверяет, можно ли интерпретировать её как команду перемещения.

Ожидаемый формат:

```text
N 5
```

где первый элемент — направление, второй — положительное целое число шагов.

Если строка корректна, парсер вызывает `Robot.move()`. Если нет — генерирует подходящее исключение. Парсер не исправляет строку и не перехватывает исключения, связанные с форматом команды: эта ответственность принадлежит `CommandReader`.

## Поля класса

### private static final String DIRECTIONS = "NSEWnsew"

Строка со всеми допустимыми символами направления на этапе проверки.

В неё включены:
- заглавные `N`, `S`, `E`, `W`;
- строчные `n`, `s`, `e`, `w`.

Строчные варианты включены не как окончательно допустимый формат, а чтобы отличить ситуацию «верная буква в неправильном регистре» от полностью недопустимого символа. После распознавания строчной буквы выбрасывается `LowercaseSymbolException`.

Модификаторы:
- `private` — поле доступно только внутри класса;
- `static` — принадлежит классу, а не отдельному объекту;
- `final` — значение нельзя переназначить.

### private final int k

Максимально допустимое значение расстояния. Передаётся парсеру при создании объекта.

### private final Robot robot

Ссылка на исполнителя, которого нужно перемещать после успешного разбора команды.

## Конструктор CommandParser(int k, Robot robot)

**Назначение:** создать парсер с заданным ограничением и исполнителем.

**Параметры:**
- `k` — максимально допустимое число шагов;
- `robot` — объект, состояние которого будет изменяться при выполнении команд.

**Возвращаемое значение:** отсутствует; конструктор создаёт объект парсера.

**Внутри:** параметры сохраняются в полях `this.k` и `this.robot`.

## Метод parse(String line)

**Назначение:** проверить строку, получить направление и расстояние, а затем выполнить перемещение.

**Параметр:**
- `line` — исходная строка команды.

**Возвращаемое значение:** отсутствует (`void`). Успешный вызов приводит к изменению координат объекта `Robot`.

**Может выбросить:** `CommandException` и его подклассы. Также вызов `robot.move()` может привести к `CoordinateOverflowException`.

### Порядок проверок

Порядок важен: если в строке несколько ошибок, первой будет обнаружена та, проверка которой выполняется раньше.

#### 1. Поиск пробела

`line.indexOf(' ')` возвращает индекс первого обычного пробела или `-1`, если пробела нет.

Если пробел отсутствует:
- цикл ищет первый символ, который может начинать число: цифру или минус;
- если такой символ находится в начале строки либо вообще не найден, строка признаётся нераспознанной;
- в остальных случаях выбрасывается `MissingSpaceException`.

Таким образом, строка вроде `N5` рассматривается как команда с пропущенным пробелом, а строка вроде `hello` — как нераспознанная команда.

Если пробел находится в позиции 0, выбрасывается `UnrecognizedCommandException`: до разделителя нет символа направления.

#### 2. Выделение частей команды

- `symbols` — подстрока до первого пробела;
- `number` — подстрока после первого пробела.

Для этого используется `substring()`.

#### 3. Проверка пробелов после разделителя

Если числовая часть начинается с пробела, выбрасывается `ExtraSpacesException`.

Если в числовой части есть ещё один пробел, выбрасывается `UnrecognizedCommandException`: текущая реализация считает дополнительные слова нераспознаваемой командой.

#### 4. Проверка числа

Сначала вызывается `checkNumber(line, number)`. Число проверяется раньше направления.

#### 5. Проверка направления

Затем вызывается `checkSymbols(line, symbols)`.

#### 6. Выполнение

Если обе проверки завершились успешно, вызывается:

```java
robot.move(direction, distance);
```

Именно здесь меняются координаты исполнителя.

## Метод checkNumber(String line, String number)

**Назначение:** проверить текст числовой части и получить расстояние типа `int`.

**Параметры:**
- `line` — вся исходная команда. Нужна для передачи исходной строки в исключения.
- `number` — текст после разделителя.

**Возвращает:** положительное целое число типа `int`, если все проверки прошли успешно.

**Может выбросить:**
- `InvalidNumberException` — строка не соответствует формату целого десятичного числа;
- `NumberOutOfRangeException` — число не помещается в `int` или его модуль больше `K`;
- `NegativeNumberException` — число меньше нуля;
- `ZeroNumberException` — число равно нулю.

### Последовательность действий

1. Проверяется регулярное выражение `-?\\d+`.
   - `-?` — необязательный минус;
   - `\\d+` — одна или более цифр.
   Если строка не подходит, выбрасывается `InvalidNumberException`.

2. Вызывается `Integer.parseInt(number)`. Он преобразует строку в `int`.

3. Если преобразование вызывает `NumberFormatException`, генерируется `NumberOutOfRangeException`. В данном контексте это означает, что число не помещается в `int`.

4. Проверяется `Math.abs((long) value) > k`. Перед вычислением модуль числа значение преобразуется в `long`. Это важно для безопасной обработки минимального значения `int`, у которого модуль не представим типом `int`.

5. Если модуль больше `K`, выбрасывается `NumberOutOfRangeException`.

6. Если число отрицательное, выбрасывается `NegativeNumberException`.

7. Если число равно нулю, выбрасывается `ZeroNumberException`.

8. В остальных случаях возвращается `value`.

Проверка модуля выполняется раньше проверки отрицательного значения. Поэтому отрицательное число, модуль которого больше `K`, сначала будет классифицировано как выход за диапазон.

## Метод checkSymbols(String line, String symbols)

**Назначение:** проверить символы направления и вернуть один заглавный символ направления.

**Параметры:**
- `line` — вся исходная строка для сообщений исключений;
- `symbols` — часть команды до первого пробела.

**Возвращает:** символ направления типа `char`, если проверка пройдена.

**Может выбросить:**
- `NotLetterSymbolException` — встречен символ, который не является буквой и не входит в допустимый набор;
- `UnsupportedLetterException` — встречена буква, не являющаяся одним из направлений;
- `MultipleSymbolsException` — записано несколько допустимых символов направления;
- `LowercaseSymbolException` — один символ направления записан строчной буквой.

### Последовательность действий

1. `symbols.toCharArray()` преобразует строку в массив символов.
2. Цикл `for` проверяет каждый символ.
3. `DIRECTIONS.indexOf(c) < 0` означает, что символ отсутствует в строке допустимых символов.
4. Если недопустимый символ является буквой (`Character.isLetter(c)`), выбрасывается `UnsupportedLetterException`.
5. Если это не буква, выбрасывается `NotLetterSymbolException`.
6. После проверки всех символов проверяется длина строки. Если она больше одного символа, выбрасывается `MultipleSymbolsException`.
7. Берётся единственный символ.
8. Если он строчный (`Character.isLowerCase(c)`), выбрасывается `LowercaseSymbolException`.
9. Иначе символ возвращается.

Порядок имеет значение. Например, `nn 5` сначала распознаётся как несколько допустимых направлений, а не как одна строчная буква. Читатель разделит её на две команды; затем каждая команда будет обработана отдельно и строчная буква будет исправлена.

## Метод isNumberStart(char c)

**Назначение:** определить, может ли символ начинать числовую часть команды.

**Параметр:**
- `c` — проверяемый символ.

**Возвращает:** `true`, если символ — цифра от `0` до `9` или знак минуса; иначе `false`.

**Внутри:** используются сравнения символа с границами диапазона цифр и проверка `c == '-'`.

Метод объявлен `private static`, потому что он нужен только внутри `CommandParser` и не зависит от состояния объекта.

## Почему парсер не исправляет команды

Разделение обязанностей — ключевое требование задания:

- парсер отвечает за распознавание корректной команды;
- исключение описывает обнаруженную проблему;
- читатель решает, можно ли исправить строку;
- исправленная строка снова поступает парсеру.

Благодаря этому парсер не зависит от источника строки. Ему безразлично, получена команда из файла, списка или другого источника.
