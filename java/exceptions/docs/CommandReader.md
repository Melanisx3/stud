# CommandReader.java — чтение команд и обработка исключений

## Назначение класса

`CommandReader` связывает источник команд, парсер и результирующий файл.

Его основные обязанности:

1. читать строки входного файла;
2. пропускать пустые строки и распознавать команду завершения;
3. передавать строки парсеру;
4. перехватывать исключения парсера;
5. исправлять те ошибки, для которых предусмотрено восстановление;
6. возвращать исправленные команды в стек для повторного разбора;
7. записывать ход обработки в отчёт.

Класс не выполняет синтаксический разбор самостоятельно: этим занимается `CommandParser`.

## Импорты

- `BufferedReader` — чтение входного файла построчно.
- `IOException` — ошибки чтения и записи.
- `Writer` — абстракция для записи отчёта.
- `ArrayDeque` — реализация стека.
- `ArrayList` — список частей команды после разделения.
- `Deque` — интерфейс двусторонней очереди, используемый как стек.
- `List` — интерфейс списка.
- `Locale` — локаль для предсказуемого преобразования регистра.

## Поля класса

### private static final String NL

Символ перевода строки, полученный через `System.lineSeparator()`. Он позволяет записывать отчёт с разделителем строк, принятым в текущей операционной системе.

### private final CommandParser parser

Ссылка на парсер, которому передаются команды.

### private final Robot robot

Ссылка на исполнителя. Нужна, чтобы после успешного выполнения команды записывать его текущую позицию в отчёт.

### private final Writer report

Поток записи результирующего отчёта. Тип `Writer` выбран вместо конкретного `BufferedWriter`, поэтому класс не привязан к одной реализации записи текста.

### private final Deque<String> stack

Стек строк, которые должны быть обработаны.

Используется `ArrayDeque`. В этой программе он выполняет роль LIFO-структуры (последним добавлен — первым извлечён).

## Конструктор CommandReader(CommandParser parser, Robot robot, Writer report)

**Назначение:** создать объект, который будет читать и обрабатывать команды.

**Параметры:**
- `parser` — объект для разбора команд;
- `robot` — исполнитель, чья позиция выводится в отчёт;
- `report` — поток, куда записываются результаты.

**Возвращаемое значение:** отсутствует; создаётся объект `CommandReader`.

**Внутри:** переданные ссылки сохраняются в полях объекта. Стек создаётся при объявлении поля и изначально пуст.

## Метод readAll(BufferedReader in, int lineNo)

**Назначение:** читать команды до конца файла или до команды завершения `X`/`Q`.

**Параметры:**
- `in` — открытый поток чтения входного файла;
- `lineNo` — номер последней уже прочитанной строки. В `Main` передаётся 2, потому что заголовок занимает первые две строки.

**Возвращает:** ничего (`void`).

**Может выбросить:** `IOException`, если чтение или запись отчёта завершается ошибкой.

### Последовательность действий

1. `in.readLine()` читает очередную строку. Цикл продолжается, пока результат не равен `null`.
2. Увеличивается счётчик `lineNo`.
3. `trim()` удаляет пробелы и другие пробельные символы по краям строки.
4. Если строка пустая, выполняется `continue`: текущая строка пропускается.
5. Если строка равна `X` или `Q`, выполняется `break`: чтение команд прекращается.
6. В отчёт записывается номер строки и её содержимое.
7. Исходная команда помещается в стек через `stack.push(line)`.
8. Вызывается `processStack()`, который обрабатывает команду и все строки, появившиеся в результате её исправления.

Обработка стека запускается после каждой исходной строки. Поэтому исправленные части одной команды полностью обрабатываются до чтения следующей исходной команды.

## Метод processStack()

**Назначение:** извлекать команды из стека, передавать их парсеру и выбирать обработчик возникшего исключения.

**Параметры:** отсутствуют.

**Возвращает:** ничего (`void`).

**Может выбросить:** `IOException`, если обработчик не может записать сообщение в отчёт.

### Последовательность действий

1. Цикл выполняется, пока стек не пуст.
2. `stack.pop()` извлекает строку с вершины стека.
3. В блоке `try` вызывается `parser.parse(command)`.
4. Если разбор и перемещение успешны, записывается сообщение о выполнении и новая позиция робота.
5. Если парсер выбросил исключение, управление передаётся первому подходящему блоку `catch`.
6. Обработчик либо исправляет команду и возвращает её в стек, либо записывает сообщение о невыполнении.
7. Цикл продолжает работу. Если исправленная строка была помещена в стек, она будет извлечена следующей.

### Почему catch расположены именно в таком порядке

Сначала перехватываются конкретные исправимые типы:
- `MissingSpaceException`;
- `ExtraSpacesException`;
- `NegativeNumberException`;
- `ZeroNumberException`;
- `LowercaseSymbolException`;
- `MultipleSymbolsException`.

Затем следует общий `CommandException`, который перехватывает остальные ошибки команды.

Последним расположен `CoordinateOverflowException`. Он не наследуется от `CommandException`, поэтому обрабатывается отдельным блоком.

Java выбирает первый подходящий обработчик. Если поставить общий `catch (CommandException e)` перед обработчиками его подклассов, последующие конкретные обработчики окажутся недостижимыми.

## Обработчики исправимых исключений

### fixMissingSpace(String command)

**Назначение:** добавить пробел между направлением и числом.

**Параметр:** исходная команда.

**Возвращает:** ничего. Исправленная строка помещается в стек.

**Может выбросить:** `IOException` при записи отчёта.

**Внутри:**
1. Цикл ищет первый символ, который может начинать число: цифру или минус.
2. Создаётся строка из части до найденного индекса, пробела и оставшейся части.
3. Вызывается `putBack()`, которая записывает исправление в отчёт и возвращает новую строку в стек.

Пример:

```text
N5 -> N 5
```

Метод не меняет букву направления или значение числа.

### fixExtraSpaces(String command)

**Назначение:** заменить последовательности из двух и более обычных пробелов одним пробелом.

**Параметр:** исходная команда.

**Возвращает:** ничего; исправленная строка возвращается в стек.

**Внутри:** `replaceAll(" {2,}", " ")` заменяет каждый фрагмент из двух и более пробелов одним.

Пример:

```text
N   5 -> N 5
```

### fixNegative(String command)

**Назначение:** удалить минус перед отрицательным числом.

**Параметр:** исходная команда.

**Возвращает:** ничего; результат помещается в стек.

**Внутри:**
1. `lastIndexOf('-')` ищет последнее вхождение минуса.
2. Строка собирается из части до минуса и части после него.
3. Вызовом `putBack()` новая команда возвращается на повторную обработку.

Пример фактического поведения:

```text
S -2 -> S 2
```

**Важное замечание:** текущая реализация только удаляет минус и не меняет направление. Поэтому это не математически эквивалентное преобразование перемещения: эквивалентом `S -2` было бы `N 2`. В документации и отчёте следует описывать именно то, что выполняет код.

### fixLowercase(String command)

**Назначение:** заменить строчную букву направления заглавной.

**Параметр:** исходная команда.

**Возвращает:** ничего; исправленная строка помещается в стек.

**Внутри:**
1. Находится индекс первого пробела.
2. Часть до пробела преобразуется методом `toUpperCase(Locale.ROOT)`.
3. Часть с пробелом и числом добавляется без изменений.
4. Результат передаётся в `putBack()`.

Пример:

```text
n 5 -> N 5
```

Использование `Locale.ROOT` делает преобразование независимым от локальных языковых настроек системы.

### removeZero(String command)

**Назначение:** обработать команду с нулевым расстоянием.

**Параметр:** исходная команда.

**Возвращает:** ничего.

**Внутри:** записывает в отчёт, что команда удалена. В стек ничего не помещается, поэтому повторного разбора не происходит.

Пример:

```text
E 0 -> команда удалена
```

Перемещение на ноль шагов не изменяет координаты, поэтому команда исключается из дальнейшей обработки.

### splitMultiple(String command)

**Назначение:** разделить команду с несколькими символами направления на несколько самостоятельных команд.

**Параметр:** исходная команда.

**Возвращает:** ничего; отдельные команды помещаются в стек.

**Внутри:**
1. Находится первый пробел.
2. До него извлекается последовательность направлений `symbols`.
3. После него извлекается расстояние `number`.
4. Создаётся список `parts`.
5. Цикл проходит по каждому символу направления и создаёт отдельную строку вида `символ + пробел + число`.
6. Второй цикл проходит по списку с конца к началу и помещает строки в стек.
7. В отчёт записывается исходная строка и список получившихся команд.

Пример:

```text
NSE 4
```

Разбивается на:

```text
N 4
S 4
E 4
```

Команды помещаются в стек в обратном порядке, чтобы при извлечении порядок выполнения остался N, S, E.

## Вспомогательные методы

### putBack(String what, String from, String to)

**Назначение:** единообразно вернуть исправленную команду в стек и записать описание исправления.

**Параметры:**
- `what` — текстовое описание выполненного исправления;
- `from` — исходная строка;
- `to` — исправленная строка.

**Возвращает:** ничего.

**Внутри:**
1. `stack.push(to)` возвращает исправленную команду на вершину стека.
2. `log()` записывает в отчёт описание исправления, старую и новую строки.

Это центральный механизм повторной обработки. Метод не вызывает парсер напрямую: повторный вызов произойдёт в цикле `processStack()`.

### isNumberStart(char c)

**Назначение:** определить, может ли символ начинать число.

**Параметр:** символ `c`.

**Возвращает:** `true` для цифр от 0 до 9 или минуса; иначе `false`.

Метод нужен для поиска места вставки пробела в `fixMissingSpace()`.

### log(String text)

**Назначение:** записать одну строку в результирующий файл.

**Параметр:** `text` — сообщение для отчёта.

**Возвращает:** ничего.

**Может выбросить:** `IOException`, если запись не удалась.

**Внутри:** вызывает `report.write(text + NL)`, то есть записывает сообщение и перевод строки.

## Пример пошаговой обработки

Пусть в файле встретилась команда:

```text
Snn-5
```

Порядок обработки по текущему коду:

1. Парсер не находит пробел и выбрасывает `MissingSpaceException`.
2. `fixMissingSpace()` добавляет пробел перед минусом: `Snn -5`.
3. Исправленная строка возвращается в стек.
4. Парсер снова получает `Snn -5`. Число проверяется раньше направления. Обнаруживается отрицательное значение, выбрасывается `NegativeNumberException`.
5. `fixNegative()` удаляет минус: `Snn 5`.
6. Строка снова возвращается в стек.
7. Парсер обнаруживает несколько символов направления и выбрасывает `MultipleSymbolsException`.
8. `splitMultiple()` разбивает строку на `S 5`, `n 5`, `n 5`.
9. Части поступают в стек в обратном порядке.
10. Парсер последовательно обрабатывает их. `S 5` выполняется; каждая команда `n 5` вызывает `LowercaseSymbolException`, после чего исправляется в `N 5` и выполняется.

Таким образом, исправления применяются по одному, и после каждого изменения строка обязательно возвращается к парсеру.

## Почему обработчики находятся в читателе

Парсер не должен знать, откуда поступила строка и каким образом её можно исправить. Он только сообщает о нарушении формата через исключение.

Читатель знает контекст обработки файла и принимает решение:
- исправить строку;
- удалить команду;
- отказаться от выполнения команды и записать причину.

Это разделение соответствует архитектуре, описанной в условии лабораторной работы.
