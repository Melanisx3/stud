# Общая архитектура и порядок работы

## 1. Задача программы

Программа моделирует исполнителя, который перемещается по условно бесконечной координатной плоскости. Команды задаются текстовыми строками:

```text
N 5
S 2
E 10
W 3
```

Буквы означают направления:

- `N` — север: увеличение `y`;
- `S` — юг: уменьшение `y`;
- `E` — восток: увеличение `x`;
- `W` — запад: уменьшение `x`.

Число задаёт количество шагов. Оно должно быть положительным и не превышать `K`. В реализации отрицательные и нулевые числа сначала оформляются как отдельные исключительные ситуации, после чего читатель пытается исправить их.

## 2. Роли классов

### Main

Отвечает за запуск приложения и работу с файлами. Открывает входной и выходной потоки, читает заголовок, создаёт остальные объекты и запускает чтение команд.

### Robot

Хранит текущие координаты исполнителя и выполняет перемещение. Он не читает файлы и не анализирует текстовые команды.

### CommandParser

Получает одну строку и проверяет её формат. Если команда корректна, вызывает метод перемещения робота. Если обнаружена ошибка, генерирует исключение. Парсер не исправляет строки и не выбирает способ восстановления.

### CommandReader

Получает строки из входного потока, передаёт их парсеру и обрабатывает исключения. Если ошибка исправима, читатель меняет только проблемную часть строки и кладёт исправленную строку в стек. После этого она снова поступает парсеру.

### Exceptions

Содержит отдельные классы исключений и связи наследования между ними. Классы исключений вынесены из остальных классов, поэтому они не являются вложенными.

## 3. Связи между объектами

- `Main` создаёт `Robot`, `CommandParser` и `CommandReader`.
- `CommandParser` хранит ссылку на `Robot` и перемещает его после успешной проверки команды.
- `CommandReader` хранит ссылки на `CommandParser`, `Robot` и объект `Writer` для отчёта.
- `CommandReader` вызывает `CommandParser.parse()` и перехватывает исключения, определённые в `Exceptions.java`.
- `Robot.move()` при переполнении координат генерирует `CoordinateOverflowException`.

Упрощённая схема:

```text
Main
 ├── Robot
 ├── CommandParser ──────> Robot
 └── CommandReader
      ├── CommandParser ─> Robot
      ├── Robot
      └── Writer (файл отчёта)

Exceptions.java
 ├── CommandException
 │    ├── UnrecognizedCommandException
 │    ├── SymbolException
 │    │    ├── NotLetterSymbolException
 │    │    ├── UnsupportedLetterException
 │    │    ├── LowercaseSymbolException
 │    │    └── MultipleSymbolsException
 │    ├── NumberException
 │    │    ├── InvalidNumberException
 │    │    ├── NumberOutOfRangeException
 │    │    ├── NegativeNumberException
 │    │    └── ZeroNumberException
 │    └── SpacingException
 │         ├── MissingSpaceException
 │         └── ExtraSpacesException
 ├── InvalidHeaderException
 └── CoordinateOverflowException
 ```

## 4. Почему используются разные виды исключений

### Проверяемые исключения — `Exception`

`CommandException` наследуется от `Exception`. Это означает, что вызывающий код должен явно обработать исключение или объявить его через `throws`.

Ошибки формата команды относятся к ожидаемым ситуациям при обработке пользовательского файла. Поэтому они представлены проверяемыми исключениями. Их наличие заставляет читателя явно определить поведение для ошибочной строки.

`InvalidHeaderException` также наследуется от `Exception`: без корректного значения `K` и начальных координат программа не может правильно начать работу. Ошибка заголовка обрабатывается в `Main`.

### Непроверяемое исключение — `RuntimeException`

`CoordinateOverflowException` наследуется от `RuntimeException`. Оно возникает не из-за неправильного написания команды, а из-за невозможности представить новое значение координаты типом `long`.

Такое исключение не требуется объявлять в сигнатуре каждого метода через `throws`. При этом в текущей реализации оно всё равно явно перехватывается в `CommandReader.processStack()`.

## 5. Порядок обработки одной команды

1. `CommandReader.readAll()` получает очередную строку из файла.
2. Строка очищается от пробелов по краям методом `trim()`.
3. Пустые строки пропускаются; `X` и `Q` завершают чтение.
4. Остальная строка помещается в стек `stack`.
5. Метод `processStack()` извлекает строку с вершины стека.
6. Читатель вызывает `parser.parse(command)`.
7. Парсер проверяет разделитель, число и направление.
8. Если проверка успешна, парсер вызывает `robot.move()`.
9. Если возникло исправимое исключение, соответствующий `catch` вызывает метод исправления. Исправленная строка возвращается в стек.
10. Цикл `while` в `processStack()` извлекает исправленную строку и снова передаёт её парсеру.
11. Если ошибка не исправляется, в отчёт записывается причина невыполнения команды.

Таким образом, одна исходная строка может пройти несколько циклов «парсер → исключение → обработчик → стек → парсер».

## 6. Почему используется стек

Стек реализован типом `Deque<String>`, конкретная реализация — `ArrayDeque<String>`.

- `push()` помещает строку на вершину.
- `pop()` извлекает строку с вершины.
- `isEmpty()` проверяет, остались ли строки.

Стек удобен тем, что исправленная команда обрабатывается раньше следующей исходной команды. Если одна команда разбивается на несколько, части помещаются в стек в обратном порядке. Благодаря этому извлекаются и выполняются в исходном порядке.

Например, строка `NSE 2` разбивается на `N 2`, `S 2`, `E 2`. В стек сначала помещается `E 2`, затем `S 2`, затем `N 2`. Извлечение даст порядок N, S, E.

## 7. Как формируются файлы

### Входной файл

По умолчанию имя — `commands.txt`. Можно передать путь первым аргументом командной строки.

### Выходной файл

По умолчанию имя — `result.txt`. Можно передать путь вторым аргументом.

Отчёт содержит:
- значение `K` и начальную позицию;
- номер и исходный текст каждой непустой команды;
- сообщение об успешном выполнении и текущую позицию;
- сведения об исправлениях;
- сообщение о невыполнении неисправимой команды;
- итоговую позицию робота.

Важно: ошибки открытия, чтения или записи файлов обрабатываются в `Main`. Если ошибка возникает при записи отчёта внутри `CommandReader`, она передаётся наружу как `IOException`.

## 8. Таблица ситуаций из задания

| № | Ситуация | Исключение | Реакция читателя |
|---:|---|---|---|
| 1 | Вместо направления не-буквенный символ | `NotLetterSymbolException` | Команда не выполняется |
| 2 | Неизвестная заглавная буква | `UnsupportedLetterException` | Команда не выполняется |
| 3 | Строчная `n/s/e/w` | `LowercaseSymbolException` | Буква переводится в верхний регистр |
| 4 | Несколько разрешённых направлений | `MultipleSymbolsException` | Строка разбивается на несколько команд |
| 5 | Нечисловой текст вместо числа | `InvalidNumberException` | Команда не выполняется |
| 6 | Отрицательное число | `NegativeNumberException` | Минус удаляется; направление сохраняется |
| 7 | Ноль | `ZeroNumberException` | Команда удаляется |
| 8 | Модуль числа больше `K` | `NumberOutOfRangeException` | Команда не выполняется |
| 9 | Строка не распознаётся как команда | `UnrecognizedCommandException` | Команда не выполняется |
| 10 | Нет пробела между символами направления и числом | `MissingSpaceException` | Пробел вставляется перед числом |
| Доп. | Несколько пробелов между направлением и числом | `ExtraSpacesException` | Повторные пробелы заменяются одним |
| Доп. | Переполнение координаты | `CoordinateOverflowException` | Текущая команда не выполняется |

## 9. Особенности и ограничения текущей реализации

1. `readAll()` удаляет пробелы по краям строки с помощью `trim()`. Поэтому ведущие и завершающие пробелы не становятся отдельными ошибками.
2. Для разделения ожидается обычный символ пробела. Табуляция не рассматривается как корректный разделитель команды.
3. Если после первого пробела встречается ещё один пробел в начале числовой части, срабатывает `ExtraSpacesException`. Несколько пробелов заменяются одним.
4. Если после числа есть ещё слова, парсер выбрасывает `UnrecognizedCommandException`.
5. Проверка числа выполняется раньше проверки направления. Поэтому в строке с несколькими ошибками первой будет обработана ошибка числа.
6. Проверка символов сначала выявляет недопустимые символы, затем несколько символов направления и только после этого — строчную букву. Например, строка с несколькими строчными направлениями сначала будет разделена на отдельные команды, а затем каждая строчная буква будет исправлена отдельно.
7. Отрицательное значение преобразуется в положительное простым удалением минуса, но направление не меняется. Это соответствует примеру из задания лишь частично: математически эквивалентное преобразование должно было бы ещё поменять направление (`S -2` → `N 2`). Текущий код реализует именно удаление минуса.
8. Значение `K` и расстояние имеют тип `int`, координаты — `long`.
9. `CoordinateOverflowException` возникает при попытке выйти за диапазон `long`. В этом случае операция не изменяет координату, для которой выполнялось переполнение, благодаря использованию `Math.addExact()` и `Math.subtractExact()`.
10. Если координата `x` или `y` уже была изменена до переполнения другой координаты, это важно учитывать при расширении метода перемещения. В текущем `switch` каждая команда изменяет только одну координату.

## 10. Дополнительная исключительная ситуация

В качестве дополнительной ситуации реализовано переполнение координат. Например, если `y` близка к `Long.MAX_VALUE`, команда движения на север может привести к значению, которое тип `long` уже не способен хранить.

Для обнаружения используется `Math.addExact()` или `Math.subtractExact()`. Эти методы выбрасывают `ArithmeticException`, который перехватывается внутри `Robot.move()` и преобразуется в предметное исключение `CoordinateOverflowException`.
