# Exceptions.java — иерархия исключительных ситуаций

## Назначение файла

В `Exceptions.java` объявлены классы, описывающие ошибки, которые могут возникнуть при чтении заголовка, разборе команды и перемещении исполнителя.

Классы исключений вынесены в отдельный файл и не являются вложенными в `Main`, `Robot`, `CommandParser` или `CommandReader`.

Основная идея — описывать разные ошибки разными типами. Тогда читатель может использовать несколько специализированных блоков `catch`, а не проверять текст ошибки или анализировать исходную строку через множество условий.

## 1. Корневое исключение CommandException

`CommandException extends Exception`

**Назначение:** общий родитель для ошибок, связанных с текстом команды.

**Поле:**
- `private final String line` — исходная строка, в которой обнаружена ошибка.

### Конструктор CommandException(String line, String message)

**Параметры:**
- `line` — исходная команда;
- `message` — описание причины ошибки.

**Внутри:**
- `super(message)` передаёт описание родительскому классу `Exception`;
- `this.line = line` сохраняет исходную команду в поле.

**Возвращает:** ничего; создаёт объект исключения.

### Метод getLine()

**Параметры:** отсутствуют.

**Возвращает:** исходную строку команды.

Метод нужен, чтобы получить команду, в которой произошла ошибка. В текущем `CommandReader` обработчики используют локальную переменную `command`, поэтому `getLine()` напрямую не вызывается, но поле сохраняет полезный контекст исключения.

## 2. Ошибка нераспознанной команды

### UnrecognizedCommandException extends CommandException

**Назначение:** строка не может быть интерпретирована как команда.

**Конструктор UnrecognizedCommandException(String line)**

Параметр:
- `line` — исходная строка.

В конструктор родителя передаётся сообщение «строка не интерпретируется как команда».

**Обработка:** отдельного специализированного `catch` для этого класса нет. Исключение попадает в общий `catch (CommandException e)` и записывается как невыполненная команда.

## 3. Иерархия ошибок направления

### SymbolException extends CommandException

Промежуточный родитель для ошибок, относящихся к символу или символам направления.

Конструктор принимает исходную строку и сообщение, затем передаёт их в `CommandException`.

### NotLetterSymbolException extends SymbolException

**Ситуация:** вместо направления встретился символ, который не является буквой и не входит в разрешённый набор.

**Конструктор:** `NotLetterSymbolException(String line, char c)`.

Параметры:
- `line` — исходная команда;
- `c` — недопустимый символ.

Сообщение включает сам символ.

**Обработка:** попадает в общий `catch (CommandException e)`; автоматического исправления нет.

### UnsupportedLetterException extends SymbolException

**Ситуация:** вместо N, S, E или W использована другая буква.

**Конструктор:** `UnsupportedLetterException(String line, char c)`.

Параметры:
- `line` — исходная команда;
- `c` — неподдерживаемая буква.

Сообщение указывает, что допустимы только N, S, E, W.

**Обработка:** команда не выполняется; срабатывает общий обработчик `CommandException`.

### LowercaseSymbolException extends SymbolException

**Ситуация:** направление записано строчной буквой `n`, `s`, `e` или `w`.

**Конструктор:** `LowercaseSymbolException(String line)`.

Параметр:
- `line` — исходная команда.

**Обработка:** специализированный `catch` вызывает `fixLowercase()`, которая переводит символ направления в верхний регистр и возвращает строку в стек.

### MultipleSymbolsException extends SymbolException

**Ситуация:** вместо одного направления записана последовательность из нескольких разрешённых направлений.

**Конструктор:** `MultipleSymbolsException(String line)`.

Параметр:
- `line` — исходная команда.

**Обработка:** специализированный `catch` вызывает `splitMultiple()`. Команда делится на отдельные команды с тем же расстоянием.

## 4. Иерархия ошибок числа

### NumberException extends CommandException

Промежуточный родитель для ошибок числовой части команды.

Конструктор принимает исходную строку и описание проблемы и передаёт их в `CommandException`.

### InvalidNumberException extends NumberException

**Ситуация:** текст после пробела не является целым десятичным числом.

**Конструктор:** `InvalidNumberException(String line, String text)`.

Параметры:
- `line` — исходная команда;
- `text` — текст числовой части, который не удалось интерпретировать как целое число.

**Обработка:** общий `catch (CommandException e)`; команда не выполняется.

### NumberOutOfRangeException extends NumberException

**Ситуация:** модуль числа больше `K` либо число не помещается в тип `int`.

**Конструктор:** `NumberOutOfRangeException(String line, int k)`.

Параметры:
- `line` — исходная команда;
- `k` — допустимый предел.

Сообщение содержит значение `K`.

**Обработка:** общий обработчик `CommandException`; автоматического исправления нет.

### NegativeNumberException extends NumberException

**Ситуация:** расстояние меньше нуля.

**Конструктор:** `NegativeNumberException(String line)`.

Параметр:
- `line` — исходная команда.

**Обработка:** специализированный `catch` вызывает `fixNegative()`. Текущая реализация удаляет знак минус и возвращает строку в стек.

### ZeroNumberException extends NumberException

**Ситуация:** расстояние равно нулю.

**Конструктор:** `ZeroNumberException(String line)`.

Параметр:
- `line` — исходная команда.

**Обработка:** специализированный `catch` вызывает `removeZero()`. Команда удаляется, в стек не возвращается.

## 5. Иерархия ошибок пробелов

### SpacingException extends CommandException

Промежуточный родитель для ошибок, связанных с разделением направления и числа.

Конструктор принимает исходную строку и сообщение.

### MissingSpaceException extends SpacingException

**Ситуация:** строка похожа на команду, но между направлением и числом нет пробела.

**Конструктор:** `MissingSpaceException(String line)`.

Параметр:
- `line` — исходная строка.

**Обработка:** специализированный `catch` вызывает `fixMissingSpace()`. Метод вставляет пробел перед первым символом числа.

### ExtraSpacesException extends SpacingException

**Ситуация:** между направлением и числом записано несколько пробелов.

**Конструктор:** `ExtraSpacesException(String line)`.

Параметр:
- `line` — исходная строка.

**Обработка:** специализированный `catch` вызывает `fixExtraSpaces()`. Несколько последовательных обычных пробелов заменяются одним.

## 6. Ошибка заголовка InvalidHeaderException

`InvalidHeaderException extends Exception`

**Назначение:** описывает ошибки в первых двух строках входного файла.

Она не наследуется от `CommandException`, потому что заголовок не является командой перемещения.

В текущем коде отдельного поля для исходной строки нет.

### Конструктор InvalidHeaderException(String message)

**Параметр:**
- `message` — описание ошибки заголовка.

**Внутри:** сообщение передаётся родителю через `super(message)`.

**Где возникает:**
- в `Main.readK()`, если `K` отсутствует, не является целым числом или меньше/равно нулю;
- в `Main.readStart()`, если отсутствуют координаты, их не две или значения не преобразуются в `long`.

**Где обрабатывается:** в `Main.main()`. Программа выводит сообщение в стандартный поток ошибок `System.err`.

## 7. Переполнение координат CoordinateOverflowException

`CoordinateOverflowException extends RuntimeException`

**Назначение:** сигнализирует о том, что после перемещения координата не помещается в тип `long`.

Это дополнительная исключительная ситуация, не обязательная часть списка из десяти ошибок формата команды.

### Конструктор CoordinateOverflowException(String message)

**Параметр:**
- `message` — описание переполнения.

**Внутри:** сообщение передаётся родительскому классу `RuntimeException`.

**Где возникает:** в `Robot.move()`. Сначала стандартные методы `Math.addExact()` или `Math.subtractExact()` генерируют `ArithmeticException`; затем робот перехватывает его и выбрасывает `CoordinateOverflowException`.

**Где обрабатывается:** в `CommandReader.processStack()`, отдельным блоком `catch`. В отчёт записывается, что команда не выполнена.

## 9. Почему нужны промежуточные классы

Промежуточные классы `SymbolException`, `NumberException` и `SpacingException` группируют родственные ситуации.

Например, в будущем можно добавить один обработчик:

```java
catch (SymbolException e) {
    // Общая реакция на ошибку направления
}
```

Он будет перехватывать все исключения, наследующиеся от `SymbolException`. При этом текущая реализация использует более конкретные обработчики для строчной буквы и нескольких символов, а остальные ошибки направления доходят до общего `CommandException`.

Иерархия также делает сообщения и типы ошибок понятными для вызывающего кода: не требуется анализировать текст исключения, чтобы понять, что именно пошло не так.
