# GameSettings

[← К оглавлению](README.md)

**Назначение:** хранит левую и правую границы и максимальное число попыток. Новый тип.

## Исходник

Файл: `src/main/java/prguesser/GameSettings.java`

```java
package prguesser;

/**
 * Настройки игры. Объект неизменяемый.
 * maxAttempts <= 0 означает, что число попыток не ограничено.
 */
public record GameSettings(int leftBound, int rightBound, int maxAttempts) {

    public GameSettings {
        if (rightBound <= leftBound) {
            throw new IllegalArgumentException("Правая граница должна быть больше левой");
        }
    }

    public boolean isUnlimited() {
        return maxAttempts <= 0;
    }

    /** Количество чисел в диапазоне. long нужен, чтобы не было переполнения. */
    public long rangeSize() {
        return (long) rightBound - leftBound + 1;
    }

    /** Сколько попыток гарантированно хватает при двоичном поиске. */
    public int optimalAttempts() {
        return Long.SIZE - Long.numberOfLeadingZeros(rangeSize());
    }

    public String attemptsText() {
        return isUnlimited() ? "не ограничено" : String.valueOf(maxAttempts);
    }

    public String description() {
        return "диапазон от " + leftBound + " до " + rightBound
                + ", доступно попыток: " + attemptsText();
    }
}
```

## Почему `record`

`record` — краткая запись класса для хранения данных. Java сама создаёт конструктор, методы доступа `leftBound()`, `rightBound()`, `maxAttempts()`, а также `equals`, `hashCode` и `toString`. Поля являются `final`. Они имеют тип `int`, поэтому объект полностью неизменяем.

Это решает пункт 8: настройки передаются одним объектом и не меняются посреди игры. Для новых настроек создаётся новый объект.

## Компактный конструктор

Блок `public GameSettings { ... }` выполняется при создании объекта. Он запрещает `rightBound <= leftBound`. Окно настроек проверяет это раньше и показывает понятное сообщение. Проверка в `record` страхует от ошибки в другом месте программы.

## Методы

| Метод | Что делает | Зачем |
|---|---|---|
| `isUnlimited()` | возвращает `true`, если `maxAttempts <= 0` | правило из пункта 2 хранится в одном месте |
| `rangeSize()` | считает количество чисел, включая обе границы | `+1` нужен, потому что обе границы входят в диапазон |
| `optimalAttempts()` | считает, сколько попыток гарантирует двоичный поиск | подсказка игроку (пункт 15) |
| `attemptsText()` | возвращает число или «не ограничено» | текст для сообщений |
| `description()` | описывает диапазон и лимит | используется в уведомлении и в логе |

### Почему `long`

Для всего диапазона `int` чисел 2³² = 4 294 967 296. В `int` это значение не помещается. Приведение `(long) rightBound` выполняется **до** вычитания, поэтому переполнения нет.

### Как работает `optimalAttempts()`

Двоичный поиск каждый раз выбирает середину и отбрасывает около половины чисел. За `k` попыток можно гарантированно различить до `2^k − 1` чисел. Поэтому нужно наименьшее `k`, для которого `2^k − 1 ≥ n`.

Это число значащих битов `n`: `64 − numberOfLeadingZeros(n)`. Для 100 чисел получается 7, для всего диапазона `int` — 33. Если лимит меньше этого значения, подсказка не означает, что победа гарантирована.
